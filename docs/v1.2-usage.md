# 阶段目标：在 Windows 上复现 V1.2 受控后端比较，并显式同步到既有 Langfuse 项目

本页给出安装、配置、compare、trace-sync及故障恢复方法。离线回放、真实模型比较、SDK协议和云端核验分别记录；真实结果见[v1.2-delivery.md](v1.2-delivery.md)。不执行V2代码Agent或部署新平台服务器。

## 1. 安装可选平台环境

Python3.11+，PowerShell无需激活脚本。原V1/V1.1命令只需基础依赖，下面为V1.2独立环境：

```powershell
Set-Location 'D:\software\codex\2026-10-26\1-repomind-codex-md-2-repomind\outputs\RepoMind'
python -m venv .venv-v12
.\.venv-v12\Scripts\python.exe -m pip install -e '.[dev,platform]'
$RepoMindExe = '.\.venv-v12\Scripts\repomind.exe'
& $RepoMindExe --version
& $RepoMindExe compare --help
& $RepoMindExe trace-sync --help
```

本机PATH缺少python时，可把创建环境命令替换为：

```powershell
& 'C:\Users\czx\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m venv .venv-v12
```

本次工作区平台环境已准备时，也可直接用 `..\..\work\v12-venv\Scripts\repomind.exe`。安装锁定Langfuse5.0.4、mem0ai2.2.1、qdrant-client1.20.0；完整解析依赖与干净安装验收以最终锁文件和交付报告为准。

不要在受控Mem0环境额外安装spaCy/fastembed模型组件；本profile会检查环境，防止隐式模型下载。它是dense受控对照，不是Mem0全功能benchmark。

## 2. 配置边界

程序从当前项目目录读取.env，系统环境变量优先。新副本可在.env不存在时复制.env.example；已有.env直接编辑，避免覆盖现有key。配置状态可用`repomind config`查看，状态中不显示key，也不发网络请求。

真实compare使用既有独立Embedding配置，不需要重新提取事件。本次模型配置沿用用户指定Qwen compatible服务；不要把DeepSeek聊天key填入Embedding项。`--vector-mode recorded`只使用明确录制资产，不发模型请求。

Langfuse由用户选择的现有项目提供三个字段；这里不预设host或地区：

```text
LANGFUSE_BASE_URL=
LANGFUSE_PUBLIC_KEY=
LANGFUSE_SECRET_KEY=
```

public/secret key属于同一Langfuse项目；保持项目与数据地区一致。字段存在不等于已经联通，只有trace-sync中的服务读回核对才能给出cloud_verified。不要把.env加入源码、报告或压缩包。

## 3. 先运行离线dev合同测试

```powershell
& $RepoMindExe compare `
  --events data/v1.2/events.jsonl `
  --dataset data/v1.2/dev/questions.jsonl `
  --vector-mode recorded `
  --vectors data/v1.2/recorded-vectors.json `
  --output reports/v1.2/offline-dev-manual-001.md `
  --run-id offline-dev-manual-001 `
  --state-dir work/v12 `
  --outbox work/v12/offline-dev-manual-001/outbox.jsonl `
  --seed 0 `
  --min-cosine 0.2
```

默认比较四variant：no_memory、repomind_semantic、repomind_hybrid、mem0。可用`--variants repomind_semantic mem0`只做主后端对照；记录选择，不能把未运行的variant当已通过。

生成同名Markdown/JSON报告、run状态和outbox。录制向量是人工理想完整事实键one-hot，仅测管线/过滤/排序，不能当真实语义准确率。它没有实际模型调用，但费用仍不是某后端“免费”的证明。

`--state-dir`是父目录，runner在其下新建run_id子目录。已存在run子目录、报告、outbox或相邻status文件会被拒绝，避免旧缓存或旧结果污染新测量。再次测量请改run-id、output和outbox路径；不要删除旧结果以假装首次运行。重传云端只复用原outbox，不重新compare。

## 4. 运行真实dev比较

真实命令将合成问题及事实键文档发送到已配置Embedding服务，产生实际用量。固定参数后再做首次holdout；这里给开发集命令，避免日常演示反复消耗保留集。

```powershell
& $RepoMindExe compare `
  --events data/v1.2/events.jsonl `
  --dataset data/v1.2/dev/questions.jsonl `
  --vector-mode live `
  --output reports/v1.2/live-dev-manual-001.md `
  --run-id live-dev-manual-001 `
  --state-dir work/v12 `
  --outbox work/v12/live-dev-manual-001/outbox.jsonl `
  --seed 0 `
  --min-cosine 0.2
```

live每variant用独立client/索引，同model/text/params分别调用；报告实际usage和输入/向量hash。若同输入向量hash不同，要保留差异flag，不能归因后端。主比较是semantic与Mem0；hybrid增加词法/RRF，只能单独解释策略收益。

compare退出0表示运行无执行错误；no_memory低分或某variant质量不如另一方，仍可能退出0。退出1表示运行含执行错误，报告仍可生成；退出2为输入/配置等错误。质量结论要看逐题结果、分母、拒答、来源和泄漏指标，不能只看退出码。

## 5. 可选价格估算

默认无价卡：金额为null，保留费用未测的原因；实际usage缺失也不能当0或免费。`price-card.example.json`只有schema和CNY币种、空models，不包含真实报价，直接使用仍会得到缺模型价卡状态。

如需估算，把空模板复制成自己的文件，再填写经过确认的模型名、每百万输入/输出价格、有效日期和出处；需要区分缓存价格时，还必须有相应usage拆分。以下只演示配置方式：

```powershell
Copy-Item price-card.example.json work/my-price-card.json
# 在本机编辑my-price-card.json，填入已确认价卡后，给compare追加：
# --pricing work/my-price-card.json
```

价卡schema为`schema_version="1"`、ISO三字母currency、models映射；每模型包含input_per_million、output_per_million、valid_from、可选valid_until/cached_input_per_million和source。金额可用十进制字符串。缺模型、过期、usage不完整或缓存拆分不足都维持null及原因。估算不是账单核验，不根据字符数猜token。

## 6. 显式同步已完成的outbox

compare只保存本地结果，不自动上传Langfuse。填写现有项目三个字段后，显式执行：

```powershell
& $RepoMindExe trace-sync both `
  --outbox work/v12/live-dev-manual-001/outbox.jsonl `
  --dataset-name RepoMind-V1.2 `
  --run-name live-dev-manual-001 `
  --receipt reports/v1.2/live-dev-manual-001-langfuse.json
```

`traces`只同步trace，`experiment`同步dataset/experiment，`both`两者都做；不写模式时默认为traces。只重放既有输出/score，不会再次调用Embedding或LLM。合成数据需明确synthetic标记；非合成记录会被阻止上传，这个版本不自动上传真实仓库内容。

receipt和outbox旁的`outbox.jsonl.status.jsonl`保留目标项目、payload身份和逐项状态：pending、sent_unconfirmed、verified或failed。flush只表示尝试发送；trace与experiment均须通过现代API读回并核对内容，才能称cloud_verified。一个dataset写入成功不能代表全部item、score和trace已持久化。

trace-sync仅在所选目标完整cloud_verified时退出0；partial为1，输入/配置错误为2。读取滞后或网络失败时保留receipt，稍后用相同outbox显式重传；不要重新跑模型。至少一次投递不保证span exactly-once，稳定ID也不能消除所有重复。

## 7. 检查结果与故障恢复

| 现象 | 含义与处理 |
|---|---|
| 缺platform依赖 | 用同一解释器安装`.[dev,platform]`，避免CLI与pip指向不同环境 |
| Mem0环境profile拒绝 | 使用隔离锁环境，避免已有可选模型组件触发下载 |
| run目录或输出已存在 | 新测量改run-id和输出路径；云端重传只复用outbox |
| cost=null | 价卡/usage未完整测量，查status；不是零成本 |
| cloud_verified=false | 查逐项状态与safe error，不能用flush成功代替云端证据 |
| index阶段中途失败 | 保留building/失败目录；runner禁止把半索引冒充ready，新测量用新run-id |
| 无证据/冲突 | 查看unknown或insufficient_evidence及来源，不强行拼确定答案 |

测试时临时目录受限，可将TEMP/TMP和pytest basetemp指向工作区。命令中的目录可按自己的路径调整：

```powershell
New-Item -ItemType Directory -Force work/tmp | Out-Null
$env:TEMP = (Resolve-Path work/tmp).Path
$env:TMP = $env:TEMP
.\.venv-v12\Scripts\python.exe -m pytest -q --basetemp work/pytest-v12-manual
```

V1/V1.1的import/query/ingest/index/search/source/eval/eval-intelligence继续保留；原数据库事件与冻结数据不改。停用platform extra可回到原运行环境，保留报告/outbox与索引，不静默删除云端对象。更详细原因、取舍与回滚见[v1.2-technologies.md](v1.2-technologies.md)、ADR0011–0014。

## 8. 等待云端可见时只读核验

首次同步返回sent_unconfirmed时，保留回执，稍后使用相同dataset-name执行以下命令。该模式不会上传或补发任何span、score或dataset。缺失保持not_verified，不能把它当完成。

```powershell
& $RepoMindExe trace-sync both --verify-only --outbox work/v12/live-dev-manual-001/outbox.jsonl --dataset-name RepoMind-V1.2 --receipt reports/v1.2/live-dev-manual-001-readback.json
```

V1.2本数据最终使用显式0.2门槛，选择仅依据dev；CLI兼容默认仍为0.55，原V1.1环境配置未改写。首轮0.55和后续0.2结果都保留，见holdout-protocol与交付报告。
