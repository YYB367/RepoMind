# 阶段目标

完成 V3.0 的有限 Harness 优化闭环。重放已记录的开发轨迹以识别问题，在开发集对照候选，然后锁定一项候选，在隔离保留任务上复测两次。

## 测量协议

历史输入仅使用 V2 开发集 r2 的真实轨迹。逐条复核 outbox 身份与摘要，回放结构化结果、工具动作和状态，只提取写入次数与代码通过但未收尾次数。历史指标提名候选，模型只收到当前任务、文件和工具结果。

候选为原始流程、压缩写入回显、根据公开状态给出收尾提示、以及两者组合。每组共用 V2 模型提示、动作 schema、无记忆上下文、同一 Docker 镜像、6 回合、20 动作、3 次公开测试调用、24,000 个上下文字符。每个任务运行顺序轮转。严格完成同时要求修改源码、正常 finish、最终公开和隐藏测试通过。

SignalBox 是新编写的合成业务代码样例。3 个开发任务和 4 个保留任务位于各自的数据目录，仓库源文件与判题也分离。开发过程只读取开发目录与公共协议。判题在模型停止后单独运行。所有输入在实际调用前冻结，并保留初次结果。

开发集按严格完成数、代码通过数、总 Token 从优到劣为非基线候选排序，仍并列时按名称排序。锁文件记录开发报告摘要、实现摘要、协议、模型和镜像。只有锁定的候选与原始流程进入保留集。保留集两轮使用相同四题并轮转先后顺序，衡量重复表现，样本仍为四个独立题目。

推荐规则要求开发集与两轮保留集均无严格完成数或代码通过数下降。开发集须取得严格完成提升，或在质量持平时节省至少 10% 的实报输入加输出 Token。两轮保留集须复现同一种提升。模型实际返回标识须跨组一致，工程错误不得进入推荐。回放只验证工程链路。

## 预算与产物

最多 12 个开发试验和 16 个保留试验，每个试验至多 6 次聊天请求，总上限 168 次。原始试验逐项落盘，重复或中断后的实验使用新目录。结果提供证据和可审计推荐，原 CLI 保持稳定。

借鉴 Harness² 的候选对照和组合，以及 Dream-RSI 将历史转成低成本反馈的思路。本项目回放只读到实际观察过的事件，候选效果由重新执行的隔离任务测量。[Harness²](https://arxiv.org/abs/2610.14224) · [Dream-RSI](https://arxiv.org/abs/2609.14858)
