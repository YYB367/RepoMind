## 技术原理和变更原因

复用 Python、原有限动作循环、TaskWorkspace、同一 Docker 镜像与固定评分，新增独立进程监管、逐请求/工具不可覆盖记录和实际 usage 校验。旧 V4.4 执行模块不改，旧输入仍可验证。新 schema 2 绑定新实现，但任务、事实、源码和公开/独立检查逐字一致，不重新选择有利任务。

旧设计拟用 deepseek-chat，当前官方接口列出的模型是 deepseek-flash/deepseek-v4-pro；本机配置为 deepseek-flash，本轮显式改为该模型，两组相同，并供用户重新确认。没有在看到成绩后调整模型、评分或源码可读范围。原不注入组继续可以读完整 page 契约。

每组 300 秒覆盖子进程初始化、HTTP、工具和最终评分；单请求 60 秒网络超时，整体硬停止可应对持续响应。请求开始先落盘，usage 与正文收到后另落盘。模型错误、截断、解析错误和传输错误停止，不进行自动重试；仍保留已返回 usage。真实输入/输出按服务整数计数核验，缓存是输入子集；未知或矛盾用量不伪造总数。具体方案比较、迁移和回滚见 [ADR 0030](decisions/0030-supervised-live-memory-effect-pair.md)。

指标定义沿用 [V4.4 指标表](v4.4-design.md)，本轮增加逐次返回模型、system_fingerprint、usage 完整性和停止回执。模型 ID 存在且全程一致、初始文件相同、两组完成、无基础设施问题且实际用量完整时才判定方向。质量可见而用量缺失，质量仍展示、总方向无法判定；金额没有账单证据始终未知。总 Token 是输入加输出，不将缓存或已经包含的推理 Token 重复累加。

## 结果与限制

当前真实方向为无法判定。尚缺注入组实际执行、两组完整且模型可比的开发结果与用量；本轮未完成的双组证据不能用模拟结果补齐。若后续另获授权补验，应作为新输入或新实验版本保留，而不是覆盖首次运行；任何提示、模型或规则变更均需另记原因。即使两组都通过，也须比较服务实际输入与输出；注入记忆增加输入而是否减少后续动作是待测事实，不能用模型自述替代可核对行为。

本题是从真实分页函数派生的受控后续任务，非完整生产仓库或第三方盲测；原源码本就含契约，持平完全合理。仅单案例、固定先无记忆后有记忆，受模型随机性、缓存和机器负载影响，不推广到全部开发任务，不据此改 reference。停止本版后不自动展开多任务实验或下一版本。
