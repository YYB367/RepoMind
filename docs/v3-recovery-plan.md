# 阶段目标

补齐 V3.0 在协议校验失败后的收尾提醒，用全新代码任务复测能否获得可重复的严格完成率或 Token 改善。

## 冻结协议

原始 V3 首轮保留试验的 hold-samples 在第 4 回合动作校验失败，距离上限还有两轮，下一轮输入只有协议诊断。该历史试验现用于问题诊断。通过旧逐试验文件 SHA-256 锁定出处，读取停止状态和下一轮反馈字段，只导出漏发位置与候选名称。

新语料 RelayBox 含 3 道开发题与 4 道保留题。两个目录分别有自己的初始源码、参考动作、公开测试、隐藏判题和 SHA-256 清单。开发阶段先比较 reference、guided-recovery、compact-guided-recovery。候选在保留集启动前锁定。只比较锁定候选与 reference，同四道保留题跑两轮。

候选的变化仅限于将可恢复的 JSON 解析与动作校验失败接入已有预算提示。组合候选还启用已有写入历史压缩。工具权限、沙箱镜像、6 回合、20 动作、3 次公开测试与最终验收标准共用。两阶段最多 150 次实际聊天请求。

沿用原 V3 推荐门槛。开发集和两轮保留集均须保持严格完成数和代码通过数。改善定义为严格完成增加，或同等质量下总 Token 降低至少 10%。两轮保留结果须复现同类改善，模型标识一致，且无工程错误。回放结果用于核验管线，实际效果由真实模型试验单独记录。

RelayBox 是本轮编写的合成 Python 样例。新保留题与原历史失败案例分离。结果只反映这组任务与模型，实际仓库和跨模型泛化仍需其他证据。
