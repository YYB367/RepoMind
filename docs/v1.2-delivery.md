# 阶段目标：完成 V1.2 Evaluation Platform 的受控比较、实际用量计量和 Langfuse 云端验收

2026-10-28交付 **1.2.0**。本轮平台工程验收完成，检索质量仍有明确限制。仅实现V1.2；未进入V2代码Agent、OpenViking或Harness优化。交付证据汇总见[acceptance.json](../reports/v1.2/acceptance.json)。

## 实际完成了什么

四种MemoryProvider在隔离的账本与索引中执行相同问题：无记忆、自研语义、自研混合、Mem0。Mem0以infer=False存相同事实键文档，检索后共享V1时间规则；主对照是自研语义与Mem0。本实验不评测Mem0原生提取、去重、冲突处理的完整流程。

Langfuse已通过真实服务读回：**80条trace、20个dataset item、8个experiment、80份逐题experiment输出及其评分**。预计算回放不再次调用模型；实际generation只在trace路径计量，experiment使用span保存原始计量metadata。最终回执为[dev](../reports/v1.2/langfuse-dev-verified.json)和[holdout](../reports/v1.2/langfuse-holdout-verified.json)。

## 为什么使用这些技术，原理是什么

| 技术 | 选用原因 | 工作原理与边界 |
|---|---|---|
| MemoryProvider | 固定输入和事实规则，减少不公平归因 | index/search统一项目、known_at、topK和余弦门槛；金标只交给评分器 |
| SQLite＋原V1 resolver | 保留历史、来源及双时间语义 | 检索事实键后从完整历史解析plan/complete/correct，避免相似计划冒充现状 |
| Mem0 OSS＋本地Qdrant | 接入可实际运行的成熟检索组件作参考 | 公共OpenAI配置连接本进程HTTP桥，再调用现有Qwen；不patch私有工厂，不隐式下载模型 |
| Qwen Embedding | 沿用用户已配置模型，减少额外服务配置 | 文本映射成1024维向量，余弦排序；相似度不是答案正确概率 |
| 混合检索/RRF | 观察词法信号对候选排序的影响 | 将词法和向量排名融合；它额外使用信号，不能当成单纯存储后端胜负 |
| Langfuse SDK5/OTEL | 连接追踪、数据集和实验并保留服务端证据 | 批量发送既有结果，读回observation/score/item并核对payload hash、内容和用量才确认 |
| 本地outbox | 网络中断后继续，不必重跑付费模型 | 稳定身份、不可变payload、按目标项目记录ACK；至少一次投递仍可能重复span |
| 实际usage＋可选价卡 | 避免猜token或将缺失费用写0 | 核对每次响应是否实报usage；未给价卡则金额null，价卡也只得到估算 |

完整说明与替代方案见[v1.2-technologies.md](v1.2-technologies.md)、ADR0011–0015；使用方法见[v1.2-usage.md](v1.2-usage.md)。

## 技术变更与原因

1. V1.1只有自研检索和本地报告。V1.2增加可选platform依赖，不强迫原用户安装SDK；旧事件协议与SQLite schema不变，停用新命令即可回到旧环境。
2. SDK版本以实际安装和公开接口核验为准。Langfuse使用5.0.4/OTEL现代实验入口；Mem0使用2.2.1，Qdrant1.20.0。Mem0没有预期的公共任意embedder实例注入，改用公共配置加本地桥，取舍是增加可见的适配开销，不修改SDK私有实现。
3. 原0.55门槛来自V1.1语料，在新dev上使纯向量Recall@3为0。仅dev比较0.2后，两种纯向量Recall@3为100%，严格正确率由2/12变7/12；因此冻结0.2再首次holdout。旧环境和CLI兼容默认0.55保留，新运行应显式传0.2。没有修改金标或按holdout调参。
4. 首次真实云端发现弃用parse_io_as_json参数返回400，且原始prompt_tokens/total_tokens会被服务重复求和。移除参数，映射为input/output/total并保留原始metadata；测试现在覆盖这两项真实差异。初始live-dev-first云端对象和失败回执留存，**不用于最终云端用量汇总**。
5. 逐题flush及立即多次轮询放大了网络等待。改为批量发送后读取，并新增--verify-only只读确认；中断前的journal保留。读回不可见时保持partial，不用重复上传假装推进。
6. 查询与resolver继续封装在既有search接口中，报告search_and_resolution合并耗时；没有为制造独立计时而改动已验收时间规则。真实云端span耗时属于回放，原执行耗时单独保存metadata。

变更原因、兼容影响和回滚细节见[ADR0015](decisions/0015-real-cloud-contract-and-read-only-verification.md)。没有数据库迁移。报告、outbox与云端对象不会随回滚自动删除。

平台环境：**426 passed**，39.49s；基础依赖环境：**407 passed，19 skipped**，27.61s。跳过项只涉及未安装的真实SDK。Qdrant本地payload索引提示保留；范围过滤已实际测试。报告见[platform XML](../reports/v1.2/pytest-platform-final.xml)、[base XML](../reports/v1.2/pytest-base-final.xml)。

## 如何运行

根目录[.env.example](../.env.example)提供空模板，本机已有.env不要覆盖。服务配置继续放在当前项目根.env；配置检查不输出密钥。

```powershell
python -m pip install -e '.[dev,platform]'
repomind config
repomind compare --dataset data/v1.2/dev/questions.jsonl --vector-mode live --min-cosine 0.2 --run-id manual-001 --state-dir work/v12 --output reports/v1.2/manual-001.json
repomind trace-sync both --outbox reports/v1.2/manual-001.traces.jsonl --dataset-name RepoMind-V1.2 --receipt reports/v1.2/manual-001-cloud.json
```

新测量使用新的run-id/报告路径；已有状态和报告拒绝覆盖。云端尚不可见时，使用相同outbox及dataset-name追加--verify-only，只读确认。compare退出0表示测量无工程错误，不保证每道质量题都通过。详细PowerShell与本机已安装环境路径见运行说明。
