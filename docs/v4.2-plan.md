# 阶段目标

从 RepoMind 自身的真实试点提名少量执行策略，在未用于此前调优的新维护任务上，补验 V3.0 的质量与 Token 改善是否可复现。保留所有旧实验；默认 reference，完成本版后停止。

## 提名与边界

V4.1 的真实 new-session.json 中，任务明确询问 codex.v4_acceptance_path，却召回另一个共享 acceptance 词的 harness.recovery_acceptance_recommendation。两条均已确认且来源正确，存在可测的上下文冗余。候选为 focused-evidence（按任务显式事实键选取）及 focused-evidence-compact（同时启用已有写入历史压缩）。压缩仍保留实际工具结果、路径和摘要，完整模型输出另存实验轨迹；不更改工具权限和停止规则。

同一真实记忆快照供所有方案使用，保留原始出处。reference 使用现有流程和完整快照；候选只保留任务显式声明的事实键，未给出明确键时保留完整快照。该实验只处理传入的已确认、同项目快照，不改产品默认召回函数，不自动写入正式记忆。

## 冻结与退出规则

冻结 3 个开发任务、4 个新保留任务，各自拥有初始源码、公开和隐藏测试及人工参考动作；任务来自 RepoMind 审核、来源和工作台维护情景，使用隔离工作副本。任务由本轮作者构造，不能称作第三方盲测或完整生产开发效果。开发与保留任务功能不同；不复用 V2 / V3 原题和旧隐藏断言。

每任务每方案仍为 6 回合、20 动作、3 次公开测试、24,000 字符上下文；每次响应最多 2,048 Token。开发共 3 方案 × 3 题，最多 54 请求。选定锁住一个候选后，保留集两轮各 2 方案 × 4 题，最多 96 请求。合计上限 150 次，不做未登记的模型预热或失败后补跑。

严格完成须代码公开/隐藏测试均通过、有实际改动且正常 finish。代码通过单列，不因达到预算就自动算完成。开发按严格完成、代码通过、总 Token、固定名称排序选候选。两轮保留均不得降低严格完成数和代码通过数，并须重现同类改善；严格完成持平时两轮总 Token 都需至少降低 10%。模型标识一致、用量完整且没有工程错误方可作晋升结论；候选不达标则 reference。

新数据、预算、评分、依赖镜像、模型配置与实现摘要在真实开发比较前冻结。开发结果摘要和候选组成选择锁，保留启动时验证一致性。隐藏结果仅供结束后评分，不反馈给当前任务。每项实际请求保留响应报告的用量；未知费用不估算人民币。首次结果和失败都保留，不能据此改题或改门槛再覆盖。

## 技术与兼容

复用 Python 有限 Agent、SQLite 记忆证据、原 JSON 传输、Docker 隔离和 V3 门槛。原镜像只有 pytest，不含核心 Pydantic；为运行 RepoMind 源码工作副本，在原不可变镜像上增加与本机相同的五项固定核心依赖，再冻结新的镜像 ID。两组共用它，原镜像和旧实验保持可用。旧协议 1/2 的行为不变，新协议只由 data/v4.2 启用。

本轮分别记录：模拟/参考动作的工程结果、真实试点证据来源、真实模型两轮效果。V4.1 已完成的网页到 Codex 会话验收沿用历史回执，本轮不把模型代码任务冒称新的跨会话验证。
