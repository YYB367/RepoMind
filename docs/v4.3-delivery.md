## 启动与操作步骤

在当前仓库根目录运行，并保持终端打开：

~~~powershell
Set-Location 'D:/software/codex/2026-10-26/1-repomind-codex-md-2-repomind/outputs/RepoMind'
$python = '../../work/v2-venv/Scripts/python.exe'
$env:PYTHONPATH = 'src'
& $python -m repomind --db work/v4.0/pilot.sqlite3 web --project RepoMind --root . --port 8768
~~~

打开 [任务工作台](http://127.0.0.1:8768/tasks)。本次使用 8768，避免影响已有 8765 服务；同库只能运行一个新版任务服务，重复启动会被拒绝。全新环境需 Python 3.11+，先执行 python -m pip install -e ".[dev]"，把 $python 换成对应解释器。运行任务还需要已安装并登录的 codex，网页不要求手填聊天 API Key。使用当前登录与模型额度。

1. 在任务页选择项目，只输入开发需求。无需输入记忆字段、值或引文。
2. 点击“检查环境与相关记忆”。页面展示项目目录、Git、Python、Codex 版本和登录检查、workspace 沙箱读写结果，以及相关已确认事实和来源。预查本身不调用模型；记忆变化后需要重新预查。
3. 点击“启动开发任务”。后端启动独立 workspace-write Codex 会话，页面轮询排队、运行或结束状态。只允许一个活动任务；重复点击不会重复执行。
4. 查看助手结果、本次修改文件及 diff，再点击自动生成的候选。会话已结束不保证需求全部完成；无改动、命令失败或候选校验失败应结合结果核对。助手没有产出足够的持久事实时，候选可以为空。
5. 审核页并排展示事实、状态、助手理由与来源正文。黄色标记为支持引文；可切换完整正文或前后文，展开本次任务的各文件差异。正文与差异支持键盘聚焦滚动。
6. 必要时编辑事实内容、类型或生效时间并保存。确认前核对版本，再点击“确认写入”和最终确认按钮；不接受则拒绝。项目、事实键和来源不在此修改。读取失败只更新预览区，不清除候选和未保存的编辑。
7. 回到任务页输入后续需求。下一任务预查及启动均从同库召回已确认记忆，不需要复制事实。历史任务可以重新打开，不会因此重跑模型。

多个项目通过仅本机可修改的配置登记，例如 work/projects.json：

~~~json
{"RepoMind":"D:/software/codex/2026-10-26/1-repomind-codex-md-2-repomind/outputs/RepoMind"}
~~~

启动时增加 --projects-config work/projects.json。网页不能上传或指定任意宿主项目目录。候选与任务接口都按项目隔离；文件路径受登记根目录、类型及大小限制。

## 文件预览规则

预览支持 Markdown、Python、JSON 和 txt，以纯文本显示，HTML/脚本不执行。当前路径校验复用原 ASCII 片段规则，中文文件名暂不支持。单文件正文上限 256 KiB，任务快照正文总预算 4 MiB，最多检查 5000 个路径。未支持的文件类型仍可在修改清单中出现，但没有正文 diff；超限差异也明确显示范围不足。

- **任务结束快照**：正文摘要与候选一致，即使工作区后来变化，仍能查看原始产出。
- **Git 提交版本**：读取候选绑定提交中的 blob，而非用当前文件代替；显示提交和摘要。
- **当前文件（摘要匹配）**：旧文件候选没有任务快照时，只有当前字节摘要一致才显示全文。
- **仅保存引文**：路径越界、缺失、文件变化且无快照、链接或大小/编码不符合要求时降级，明确提示不代表完整原文。

本次 diff 使用任务启动前后快照；不把开始前已有的工作区差异混入本次任务。存在其他进程同时修改同项目时仍可能混入外部变化，应串行使用。路径、原文和模型输出全部当作数据处理，来源匹配不等于自动证明事实语义正确。

## 技术原理、文件变更、迁移与回滚

Python 标准库 HTTP 继续服务静态页面与 JSON，后台线程复用原 Codex 包装器，每任务独立会话。SQLite 新增 web_tasks、web_task_candidates 和 memory_review_notes，记录状态、前后文件和候选关联；无需第二个数据库或外部队列。候选理由单独存表，旧 candidate_json 不增加字段，兼容旧版严格解析器。正式确认继续复用原事务、revision 和幂等规则。

新增 web/tasks.py 负责预查、任务租约与后台执行；web/evidence.py 负责受限文件读取、摘要匹配和 diff；tasks.html/tasks.js 提供任务页，原 app.js/style.css 加入独立预览区及响应式并排布局。server.py 增加项目登记和接口；codex_cli.py 复用执行并记录用量/命令失败；codex_flow.py 增加可选理由约定。工作台分页函数及测试是此次真实任务的产出。详细取舍见 [ADR 0027](decisions/0027-web-tasks-and-versioned-evidence.md)。

对比过引入完整 Web 框架/消息队列与保存全仓库，当前单机单任务适合复用已有服务和有上限的文本快照。命令按参数数组执行、不拼接任务为 shell；项目 Git 信任仅限单次已选择仓库的读取命令，不改全局配置。依据 [官方非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode) 使用 JSON 事件与 workspace-write；Windows 行为以本机探测和实际会话为准。

SQLite user_version 仍为 2，三个表按需添加；原事件、来源和默认 reference 保持兼容。停止服务会请求终止正在执行的 Codex 进程，异常退出后仍需人工核对遗留进程与文件，不自动重跑。回滚时先停新服务，切回 v4.2.0 并用旧 CLI/网页读取同库；新表保留即可，不删除任务或正式记忆。任务快照已保存，原文路径后来变化时仍按匹配的历史证据读取。

原有未跟踪 docs/memory-daily-use.md 保留原样，不纳入本版提交。旧冻结数据与首次报告逐字节核对；发布包不含 .env、本地数据库或任务锁文件。当前同库服务仍在 8768 提供查看。
