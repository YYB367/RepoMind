# 阶段目标

让用户核对“注入已确认记忆后，结果或成本是否变化”。本次只交付最小双组设计、可视化和无模型流程验证；真实效果、Token 差异和金额仍未测量。真实调用需先审阅确切发送内容和预算，当前没有 live 入口。

## 对照单位与唯一输入差异

第一例从 v4.3.1 提交 8994148e61a2548461db152a785920b0ba1f453c 的 workbench.py 提取自包含 page 函数，保留逐字源码和摘要，放入独立样例 src/pagination.py，并添加待实现的 page_query stub。任务要求在不改变 page 契约的前提下把查询参数适配为 offset/limit，处理 ASCII 数字串、默认值和不修改输入。它是从真实项目派生的受控后续开发题，不是完整生产仓库，也不会自动把实验实现合并进产品。

两组共有：相同初始源码、公开测试、任务文字、系统提示、工具能力、沙箱镜像、验收检查与预算。不注入组的 memory.facts 是空列表，注入组是冻结的 workbench.page / pagination_validation 事实及 source_id、event_id、相对来源路径、提交信息和 SHA-256。每组新建独立 Git 副本与执行器，第一组结果和工具反馈不传给第二组，没有经验库或候选写回。

空列表只代表没有 RepoMind 注入；源码本身仍然包含分页类型与范围检查。不能为了显示提升而删去对照组本来可读的代码。若模型自行读出契约，两组完全可能持平。

事实由原只读 recall 从 RepoMind 项目的当前有效已确认事件选出，再绑定冻结时间。它验证的是给定这条事实后开发过程的增量差异，不测召回准确率。之后账本更新不会改变已冻结配对；新快照必须创建新输入版本。来源是历史审核证据，路径相对化不改 source_id/摘要。

## 固定条件

| 条件 | 两组共同设置与核对方式 |
| --- | --- |
| 起点 | 初始允许文件逐字节 SHA-256 相同；开始前核对，结束后保留 diff |
| 模型 | 本次无模型，同一 ReplayAgentProvider 脚本；未来拟用同一 DeepSeek deepseek-chat、temperature=0、thinking disabled，执行前核实服务支持与每次返回模型 ID |
| 工具 | list_files、read_file、write_file、run_tests、git_diff、finish；不开放 shell、网络、安装或额外工具 |
| 权限 | 只允许写 src/pagination.py；公开测试和 README 受保护，模型看不到评分脚本和回放解答 |
| 测试沙箱 | 同一个不可变本地 Linux 镜像；禁网、非 root、只读挂载、256 MiB、1 CPU、64 PID、每次测试超时 25 秒和输出上限 64 KiB |
| 动作预算 | 每组最多 6 回合、20 动作、3 次代理公开测试；每次最多 4 动作；上下文最多 24000 字符，记忆也计入预算，不为处理组追加额度 |
| 最终验收 | 每组再独立执行同一份公开检查一次、固定验收一次；不反馈验收输出给执行器 |
| 未来模型预算 | 每组最多 6 请求、总共 12；每请求最多 2048 输出 Token；总输出上限 24576 Token；无自动重试或自动补跑 |
| 顺序 | 本例固定先不注入再注入；耗时受顺序、缓存和宿主负载影响，不作为稳定因果证据 |

冻结文件、协议、模型可读文件、公开检查、固定验收、回放动作和未来发送清单均有摘要。协议另绑定执行器实现与系统提示摘要。实际交给执行器的初始消息与发送清单逐字比较；该回归曾发现 JSON 键序不一致，已在首次真实请求之前修正并冻结新版本，不改变评分。

旧 V4.3.1 Codex 包装器用于日常开发，无法在本轮接口中逐项固定其隐含工具与模型参数。本例因此复用已有有限动作执行器和 Docker，而不把日常 Codex 会话和另一个执行器混作两组。未来结论仅适用于这个受控执行器，不能直接外推 Codex 桌面应用效果。

## 预先固定的验收

公开检查 3 项：默认分页、数字字符串分页、忽略无关参数。独立检查 24 项：offset/limit 类型与范围、bool、负数、小数、None、空串、符号/空白/非 ASCII 数字、空页、前导零、不修改输入、params 类型及既有 page 行为。先冻结后执行，两组使用同一文件和同一 expected_count；隐藏只指执行器不可见，不代表第三方盲测。

严格完成要求：执行器 finished、有源码改动、保护文件未变、最终 27 项检查全部通过且无基础设施问题。模型的 finish、自述“完成了”或自己报告“测试通过”都不能替代独立回执。跳过、少收集或未执行不算通过。

## 指标与能够支持的结论

| 指标 | 定义及证据 | 可以支持 | 不能支持 |
| --- | --- | --- | --- |
| 记忆输入 | input.json 中的 facts、来源 ID/摘要；实际首轮消息与冻结发送清单一致 | 哪些记忆确实进入输入，哪组为空 | 模型内部注意了哪条记忆、长期记忆效果 |
| 严格完成 | 上述条件全部满足则 1，否则 0 | 本题按既定规则完成 | 未覆盖功能都正确、产品已上线 |
| 检查通过数 | 结束后的最终公开 3 项及独立 24 项 passed 之和，合计 27 | 这批行为在该副本上的检查结果 | 通用代码质量或模型准确率 |
| 工具/命令记录 | 允许工具、路径、状态，测试的实际退出码和脱敏输出 | 执行器读取、修改和测试的轨迹 | 任意 shell 权限或模型因果意图；非命令工具没有退出码 |
| 总耗时 | 从创建该组副本至最后验收结束的 perf_counter 墙钟秒数 | 这次本机流程用时 | 离线脚本耗时等同模型延迟，或一次较快就是稳定改善 |
| 动作耗时 | run_agent 期间累计墙钟时间，排除最后独立评分和副本准备 | 执行动作阶段的时间 | 仅模型生成耗时 |
| 输入/输出 Token | 未来服务逐次实际 usage 累加；缺失保持未知 | 服务报告的处理量 | 用字符或字节推算的伪精确实际用量 |
| 缓存输入 Token | 输入 Token 的子集，单列而不重复相加 | 该次服务缓存使用 | 直接代表金额折扣或去掉它后称“总 Token” |
| 总 Token | 实际输入加输出，推理输出若已含于输出不再重复 | 同条件下的服务总用量差异 | 实际账单、时间或质量 |
| 金额 | 当前无账单/可靠计费证据，保持未知 | 取得计费证据后再讨论开销 | 仅按 Token 或模型名称编造真实金额 |
| 自述 | 未来模型最终摘要原文，独立展示且不评分；本轮只有脚本说明 | 模型说了什么 | 它确实用了记忆的证明 |
| 实际行为 | 已读文件、改动、diff、测试回执 | 具体可检查产出 | 证明模型内部因果路径 |

真实执行只有条件一致、两组完整、返回模型可比且用量完整，才给出改善/持平/下降；若质量和 Token 反向变化，显示取舍，不合并成单一“胜率”。质量可见但用量缺失时，质量单列、成本未知；传输或沙箱问题则不可判定。单对任务只是观察，不能证明可复现改善、统计显著性或改变 reference 策略。若要稳定结论，需要新增未调优任务、重复配对和交叉运行顺序；这些不属于本阶段。

本轮因为没有模型，方向固定 not_measured。脚本两组都 27/27 只说明流程能完成，不是“记忆效果持平”。不同方向的单元用例仅验证显示/判定逻辑，不当作真实实验成绩。

## 真实调用前还需什么

[data/v4.4/outbound-review.json](../data/v4.4/outbound-review.json) 是确切初始消息与全部可读原文件，且已纳入冻结摘要。未来拟发送至 https://api.deepseek.com/chat/completions：同一系统提示、任务、只读文件清单、各组记忆输入；后续只有允许源码/公开测试的读取结果、生成代码、公开测试反馈与 diff。模型不能读取整个 RepoMind 仓库或其他文件。

不发送 .env、密钥、整个账本、聊天记录、独立验收源码、评分反馈或 offline-actions.jsonl 参考解答。凭据仅用于 HTTPS 身份认证，不放入输入和报告。

拟议单轮双组最多 12 请求，每组 6 回合、20 动作、3 次代理公开测试；最多 24576 输出 Token，温度和输出长度固定。上下文每次最多 24000 字符，最多 12 次就是 288000 字符的请求上下文上界，**不是输入 Token 上限或费用承诺**。真实输入 Token 和金额尚未知。模型错误/截断/解析失败也消耗请求配额，不自动追加次数。

当前没有真实执行入口，--live 会被拒绝。执行真实实验前还需：用户授权该发送范围和预算；实现并测试真实配对入口的 300 秒每组时间限制、请求总数、每次请求大小、模型返回标识/用量一致性和停止后的证据保留；绑定新的实现摘要并保留本次冻结版本。仅批准预算不自动代表原生 Codex 流程也已验证。未完成这些门槛前保持无调用，不把后续真实工作说成已经验收。
