## 为什么采用这些技术，原理是什么

| 技术 | 为什么适合这一阶段 | 在本项目中如何工作 |
|---|---|---|
| Pydantic动作协议 | 把模型建议变为可检查请求 | 限定6类工具、每批最多4动作，finish独占；合法JSON仍需权限校验 |
| 小型有限循环 | 便于解释停止、重试和成本 | 6回合、3次公开测试、20动作、24K字符上限；没有通用shell或框架隐式工具 |
| Docker Linux | 临时目录不能隔离普通Python | 禁网、非root、去capabilities、只读root/挂载、CPU/内存/PID/时间/输出限制 |
| 冻结manifest＋文件白名单 | 避免额外文件和凭证混入任务 | 只复制登记源码/配置；拒绝.env、.git、路径越界、link/reparse point/hardlink和测试写入 |
| 既有V1 resolver | 保留计划/完成、纠错和双时间解释 | 用明确事实键取当前或任务时点事实，避免把V1.2语义召回弱点混入执行对照 |
| 独立SQLite经验库 | 让成功经验跨任务持久化又可追溯 | 最终验收通过后才记录公开总结；只读同run/同项目较早任务，隐藏判题不写入 |
| DeepSeek JSON适配 | 重用已有接口和真实usage计量 | schema校验后分派工具；逐请求保存当时消息快照和服务计数，不让模型决定权限 |
| Langfuse SDK5/outbox | 在网络波动下保留可核对实验 | 只回放预计算结果，generation计数不在experiment再记一遍，verify-only不补发数据 |

完整工作链路、替代方案及限制见[v2-technologies.md](v2-technologies.md)和ADR0016–0019。工具执行权限由宿主决定；模型文本、记忆和经验均不能扩权。

## 技术变更及理由

1. **V1.2检索平台→V2代码执行**：加入Docker，因为子进程改变cwd不能阻止读宿主或联网。本机已有Linux引擎，未新装云服务/虚拟机栈；旧命令仍不依赖Docker。容器共享内核，不是绝对防护。
2. **提取/检索模型调用→有限JSON动作循环**：重用HTTP适配而不引入Agent框架，权限仍在工具层；输入/源码不能要求执行任意shell、安装依赖或读取隐藏测试。网络传输错误停止任务，不盲目付费重试。
3. **统一当前事实→显式三组消融**：baseline无历史，memory读取冻结当前快照，enhanced按任务as_of/known_at并附带经验。时序和经验同时改变，不能分别归因，也不代表所有Memory Agent。
4. **语义检索→本轮显式键路由**：这是为减少已知语义误召回的混杂，不是宣称修好了V1.2主体歧义或提前实施V2.1上下文系统。
5. **原始任务→输入r2**：dev-01写“拒绝bool”却未说明异常类型，三组原结果均用了TypeError，而预先存在的隐藏断言只接受ValueError。只补明公开契约，全部隐藏断言和其他任务字节不变，原数据及原成绩保留；没有放宽金标迎合模型，也没有删掉失败案例。前后差异含输入澄清、经验变化和生成波动，不全部算系统提升。
6. **目录遍历复制→只复制manifest登记文件**：复核补上额外.env混入的防线，甚至错误登记的凭证文件也拒绝；原冻结样例的实际可见文件没有改变。

没有核心SQLite schema迁移；经验使用独立库。停用agent命令即可回到V1.2；回滚保留任务副本、报告、数据库和云端对象，不静默删除。发布版仅更新版本元数据/文档，真实候选版rc1报告不改写成新执行记录。

hold-01还暴露了业务规格限制：三组都先舍入折扣额再扣价，金标则对精确余额舍入。原任务对舍入位置未充分消除歧义，不能简单称为“不懂ROUND_HALF_UP”。本轮没有观察holdout后修改输入、判题或剔除该项；它限制了该小基准的解释力，应在独立审查后的新数据版本中澄清。

## 如何运行

本机已有独立V2环境和测试镜像；根.env继续使用现有DeepSeek/Langfuse配置，密钥不进容器或分发包。完整安装和源码包位置说明见[v2-usage.md](v2-usage.md)。从项目根目录复制：

```powershell
$RepoMindExe = '..\..\work\v2-venv\Scripts\repomind.exe'
& $RepoMindExe config
& $RepoMindExe agent-doctor --sandbox-config work/v2-sandbox.json
& $RepoMindExe agent-bench --data-root data/v2-r2 --dataset data/v2-r2/dev/tasks.jsonl --provider live --run-id manual-001 --output reports/v2/manual-001.json
```

新机器先启动Docker Desktop Linux引擎，再显式agent-prepare构建镜像。wheel不含Docker镜像或样例数据，构建应在源码包根目录，或指定--project-root。新测量用新run-id和输出路径；程序拒绝覆盖既有状态。同步云端只复用outbox，等待可见时加--verify-only，不重跑模型。

## 尚未解决的问题

只覆盖10个记忆依赖明显的合成Python任务，作者与实现者同会话，不是生产或独立盲测；六轮预算下正常finish与代码通过并不等价。时序和经验联合，无法独立归因。当前记忆快照对历史任务的定义有意不同于增强组，不能外推所有记忆框架。

容器/镜像/控制器和Linux内核必须可信；Python判题共享进程，结束标记不能防蓄意伪造测试结果，不支持任意外部仓库。没有货币实付核验，至少一次同步仍可能有重复span；模型服务与网络波动限制复现。V1.2语义检索弱点保留，未以V2绕过或宣称修复。下一阶段仍需用户明确授权。

保留集未证明完整流程增益，且折扣舍入位置仍有契约歧义；工程测试通过不代表任务效果验收全部通过。
