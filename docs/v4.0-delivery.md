# 阶段目标

让 RepoMind 在一个真实 Codex 会话结束时生成待审候选，经用户确认后，由另一个独立 Codex 会话按项目与任务获取事实及来源。

## 运行方法

在仓库根目录安装 RepoMind，并确认本机 codex exec 可登录运行。工作区现有 Python 可通过 PYTHONPATH=src 使用源码。

~~~powershell
$ledger = 'work/v4.0/pilot.sqlite3'
python -m repomind --db $ledger codex --root . --project RepoMind run --prompt '完成项目任务并保留可核对的交付记录'
python -m repomind --db $ledger review list --project RepoMind --status pending
~~~

包装器每次启动一个独立的 codex exec 会话。需要文件改动时可显式传 --workspace-write，让 Codex 按自己的工作区沙箱策略运行。读取建议和候选后，用原 review show、edit、confirm 或 reject 处理。确认时使用审核过的候选 ID 和 revision。之后用同一个库启动下一任务，包装器会自动查找相关事实，调用者只提供任务内容。

原生路径为项目生成配置。已存在的 .codex/hooks.json 应先核对并合并定义。生成器只创建新文件。

~~~powershell
python -m repomind --db $ledger codex --root . --project RepoMind hooks-config --output .codex/hooks.json
~~~

在 Codex CLI 的 /hooks 或桌面应用的 Hooks 设置中核对项目配置并建立信任。之后可照常开启本地会话。项目层未获信任时，可以使用上述包装器。配置记录了生成时的 Python、工作区与库位置。迁移目录或解释器后需要重新生成并审核定义。[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)

## 工作原理与文件变更

SessionStart 给出任务结束时提交结构化候选的约定。UserPromptSubmit 用任务词匹配同项目已确认事实。Stop 处理最终回复末尾的候选块，验证确切引文再写入待审表。包装器使用相同的候选生成和召回函数。两条路径都由 V3.1 的审核命令完成正式写入。

codex_flow.py 实现候选校验、作用域和查询，codex_cli.py 提供 hook 配置、原生事件入口和 Codex 包装器。scripts/repomind_codex_hook.py 为源码工作区提供启动入口。adapters/sqlite.py 新增只读连接选项，tests/test_codex_flow.py 覆盖审核隔离、来源和包装器协议。[ADR 0024](decisions/0024-codex-lifecycle-with-explicit-review.md)

已有 SQLite 库无需迁移。回滚时可从 Codex 禁用项目 hooks，恢复 V3.1 的运行方式。已确认事实仍由原账本读取，历史冻结材料和 reference 策略保留。

**V4.0 的显式包装器路径通过真实两会话验收。** 本机 codex-cli 0.166.0-alpha.6 将 hooks 列为稳定且启用。Windows 三个生成命令用模拟载荷执行成功，验证了输出协议。原生会话触发尚待在受信任项目中运行验证。[模拟事件回执](../reports/v4.0/native-contract.json) · [官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)

真实会话 A 完成了 RepoMind 既有补验的只读审计。此前尝试遇到默认只读限制和 Windows 工具沙箱启动故障，因此由外层验收脚本从真实报告提供任务证据片段。包装器自动生成候选，并把引用及摘要与既有 Git 对象核对。确认前召回为空。用户明确批准第 1 版后才进入账本。[会话 A](../reports/v4.0/session-a.json) · [人工确认回执](../reports/v4.0/user-approval.json)

独立会话 B 只接收后续任务和待查键。包装器从同库召回 reference、原报告路径和来源 ID。会话 B 据此写出下一轮验收交接，要求核对实际执行策略，并逐字引用了来源 ID 和路径。其他项目同任务词召回为空。本机试点库位于 work/v4.0/pilot.sqlite3。[会话 B](../reports/v4.0/session-b.json) · [机器验收](../reports/v4.0/acceptance.json)

全量 pytest 485 项通过，零失败、零跳过，包括四项真实 Docker 隔离用例。另有一条既有 Qdrant 本地索引警告。模拟测试、真实 Codex 会话回执分别归档。本版没有运行新的执行策略对照或 RepoMind 提取模型实验。[JUnit 回归](../reports/v4.0/pytest-platform.xml)

## 尚待验证的范围

替代路径的手动步骤是启动每个包装器会话与审核候选。实际 Windows 会话验证覆盖只读审计与后续交接，工具沙箱中的项目写入尚未通过这次试点。原生接入需要一次项目配置与 Codex 信任审核，并在真实任务中复测。任务词匹配对同义改写有限，省略结构化块时可用原 review 命令补录。
