# RepoMind V1 需求与发布验收

版本：V1.0；设计日期：2026-10-26。需求优先级：用户本轮请求 > 执行提示词 > 背景规划归档。规划中的后续能力不属于本轮授权范围。

## 目标与用户故事

RepoMind V1 是可独立运行的结构化项目记忆 CLI。开发者导入多个会话的项目事实后，进程退出再启动仍能查询历史和当前决策，并取得来源。评测用于证明规则行为，不代表已有真实编程 Agent。

- 维护者查询 CampusRecruit 2 月数据库时得到 MySQL；3 月有迁移计划时仍得到 MySQL；完成记录生效后查询 4 月 10 日得到 PostgreSQL。
- 审计者查询当时已知信息时指定 known_at，避免后来纠错静默改写“当时所知”。
- 同时维护三个项目的开发者必须明确指定项目，另一个项目的同名字段不影响答案。
- 数据整理者可以重复导入；相同事件不会增加，错误行和 ID 内容冲突可定位且整批失败。
- 信息不足时使用者得到 unknown；同时间未消解矛盾得到 insufficient_evidence 和冲突来源。
- 评审者可以用固定命令复现测试、开发集和保留集报告。

## 功能要求

| 编号 | 要求 | 验证方式 |
|---|---|---|
| F01 | UTF-8 JSONL 结构化导入；Pydantic 校验所有字段，拒绝未知字段、空 ID、无时区时间和非法状态 | 模型与 CLI 错误测试 |
| F02 | SQLite 保存完整账本、原始事件和替代关系；整批事务；重复导入幂等 | 重启进程、回滚、重复 ID 测试 |
| F03 | plan 不投影事实；declare/complete 生效；correct 指向明确历史事件且不抹去后续状态 | 状态与纠错链测试 |
| F04 | 精确 project_id + subject + predicate 检索；as_of 有效时间，known_at 可选观察时间 | 隔离与双时间测试 |
| F05 | ok 返回值和来源；unknown 无伪造值；冲突返回 insufficient_evidence | 拒答、同时间冲突、来源断言 |
| F06 | CLI 至少 import/query/eval/help；成功输出可解析 JSON，错误返回非零码 | 子进程端到端测试 |
| F07 | 约 60 事件、3 项目、48 题，六类各8；32开发/16保留 | 数据集结构审计 |
| F08 | 自动生成 JSON、Markdown 报告；含分类准确率、拒答、项目串用、引用、耗时、配置与失败阶段 | 独立评分器及评测集验收 |

## 非功能要求

- Python 3.11+，Windows PowerShell 可复制运行。业务仅依赖 Pydantic 和标准库；pytest 作为开发依赖。
- 同样账本、查询和配置产生同样答案；elapsed 时间不要求逐字相同。
- 不使用网络或模型服务完成导入、查询和评测。运行不需要 API 密钥。
- 保留原始历史；SQL 参数绑定；不执行输入中的代码。事件来源仅供审计引用，不提供来源真实性认证。
- 精确字符串匹配；不推断数据库品牌别名、自然语言时间或动态项目权限。
- 小数据集全量状态解析优先可解释；不声称已做大规模性能、并发、灾难恢复或长期线上稳定性验证。

## 本轮明确不做

不实现 LLM、Embedding、自由自然语言问答、Mem0/OpenViking/Langfuse 集成、云部署、Docker、Redis、LangChain/LangGraph、GUI、真实代码修改 Agent、多 Agent 产品和 Harness 自优化。开发阶段的工程协作不成为产品能力。仅允许在文档说明版本演进。

## 版本闸门

P0 闸门：architecture.md、requirements.md、evaluation-plan.md、ADR 和 README 数据协议足以指导实现；模型、时间语义与评分协议一致。

V1 发布必须同时满足：

1. 持久化跨 CLI 进程通过；重复导入无新增事件。
2. 项目串用 0 次，计划不能提前更新实际状态。
3. 历史/当前查询和纠错/冲突核心测试全部通过，来源能回查。
4. 固定命令产生完整 JSON/Markdown 报告，失败样例不可隐藏。
5. 保留集16题至少13题正确；同时披露样本量与模板限制。
6. README 提供已验证环境、安装与 PowerShell 演示；缺依赖或环境阻塞如实记录。
7. 失败时修复实现，不修改已冻结标准答案迎合输出；保存旧报告与基线。

通过后停止于 V1。V1.1 的事实提取与语义检索仅列为下一版本建议。
