# 阶段目标

交付按项目隔离的上下文选择和 OpenViking 只读适配，测量直接加载、向量检索、L0/L1/L2 分层加载的质量和开销。

同一个项目内三组共享原文、题目、短答提示词、模型和完整证据记录的打包规则。固定预算为 640 和 1800 UTF-8 字节。预算含证据 JSON 的结构开销，模型账单以服务返回的输入和输出 Token 为准。资料包含两个合成项目，部分文档 ID 相同，验证选取范围。用 2 题作开发检查，8 题作首次保留集。将语料、开发题、保留题哈希存入清单。题目和资料在同一开发会话编写，结果适用于这个小语料。

每题按轮转顺序测量六个条件。直接加载从清单顺序打包。向量策略对同项目原文做 Embedding，以余弦排序，单独记文档索引的请求、Token 和耗时。分层先在项目的 L0 摘要中排序，至多进入两个目录读取 L1 概览，最后按查询与条目描述的匹配程度选择 L2。三组只把选中的完整 L2 原文交给同一个回答器。跳过装不下的条目，保留给更短条目的机会。

主指标为短答和引用同时正确，忽略大小写、首尾空白、分隔斜杠周围空白以及引用顺序。证据命中要求全部金标文档入包，拒答题单列。记录检索时长、读取体积、注入体积、实际模型输入和输出 Token、调用失败及向量索引成本。保留组首次真实运行留档，后续复测单独编号。

工程验收包含本地预算和项目隔离测试、真实聊天与 Embedding 对照以及 OpenViking 服务读取实测。OpenViking 实测独立于冻结语料上的三组对照，目录摘要的来源与质量分别记录。
