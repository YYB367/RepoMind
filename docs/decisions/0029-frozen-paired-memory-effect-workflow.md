# 阶段目标

交付 V4.4 记忆效果对照的可审查设计与无模型流程，固定比较条件并明确实际效果仍待真实实验。

# ADR 0029：冻结快照、独立副本、独立验收与只读结果页

状态：采用设计与离线实现；真实调用未授权、未实现执行入口。

V4.3.1 解决单任务运行反馈，不能把不同起点、模型或任务的历史耗时直接拿来证明记忆收益。本轮新增配对流程，不改变日常任务策略或正式记忆。事实经原 recall 只读选取后冻结，而非两组运行时分别检索，避免中途审核变化成为第二个因素。

选择已有有限动作循环和 Docker，因为能控制每次可见文件、唯一可写文件、动作/测试/上下文预算和独立评分。没有把原 Codex 包装器与另一执行器互比，也未宣称本例代表 Codex 全应用效果。对比过直接重放两次日常任务、让模型自己打分和一次拷贝全仓库：分别无法固定条件、自评不可复核和容易泄漏记忆/来源。最小冻结样例更适合先审计变量，代价是外推范围小。

协议绑定源码来源、任务、系统提示、实现摘要、镜像、已确认记忆、公开与独立检查；副本彼此隔离，保护文件不能写，评分在结束后进行且不回传。实际首轮消息与冻结发送清单逐字比对，避免“展示的记忆”与实际输入不同。首次试图使用的历史镜像已从本机丢失，第一份输入与失败保留；用原 Dockerfile 重建后记录新 ID、新冻结版本，没有改评分要求。

结果用原 Python HTTP 静态页面和 JSON，继续沿用蓝/灰界面、系统中文字体与左右同指标排版。JSON 文件便于逐字保留首次结果，无需新增 SQLite schema。只读 view 服务不取得任务服务租约，可以和用户暂不停止的旧工作台共存；该服务拒绝所有写接口。报告只从配置目录按项目和受限 ID 读取，拒绝越界/链接/过大文件，DOM 使用 textContent。

仅运行固定回放，不导入/实例化 LiveAgentProvider，因此本轮不存在模型调用通道。未知 Token 保持 null，与已知模型请求数 0 分开。先显式给出预算和内容，再开发经测试的真实执行门槛，避免网页查看结果变成隐式花费额度。

技术变更为新增 memory_effect.py、memory_effect_cli.py、comparisons.html/js、两个读取接口及导航，复用 AgentTask、TaskWorkspace、run_agent、DockerSandbox 和 recall。不改原 SQLite、审核/候选规则、工作台任务执行或 reference 默认值；无需记忆迁移。

回滚先停止新查看进程，切回 v4.3.1。保留 data/v4.4*、reports/v4.4 和离线运行目录；不改原库、不删除首次失败。旧版看不到新页面。新镜像与旧镜像 ID 无法互换，需要重建时另建输入版本，不能覆盖原协议。

结论边界、指标计算和未来门槛详见 [V4.4 设计](../v4.4-design.md)。
