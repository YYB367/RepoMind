# 阶段目标：为 V1.1 增加按事实键和观察快照的混合检索

ADR 0006；状态：接受；日期：2026-10-27；范围：V1.1。

## 原方案与触发原因

V1 按 project_id、subject、predicate 精确查询。用户必须记住字段名，自然语言近义表达无法找到键。本次增加Embedding候选检索，原有精确入口继续保留。

## 替代方案比较

| 方案 | 优点 | 取舍 |
|---|---|---|
| 仅精确键/词法匹配 | 简单、确定、专有名词可检查 | 保留为基线和无Embedding服务时的显式lexical模式；不能声称语义检索 |
| 仅向量相似度 | 有机会关联不同措辞 | 对精确名词和未知问题可能不稳，增加服务和缓存依赖 |
| 向量与词法按RRF融合 | 两种线索互补，避免直接相加不同量纲分数 | 采用；需固定算法配置、阈值与数据独立评测 |
| 相似事件直接作为答案 | 实现较短 | 计划或旧事件可能压过当前事实；不采用 |
| 独立向量数据库/框架 | 扩展索引能力 | 当前规模不需要部署；以后有性能证据再决策 |

## 决策与原理

候选单位为 `(project_id, subject, predicate)` 事实键。先过滤项目与可选known_at，再用predicate及该快照历史values构建文档。向量余弦相似度和词法分数分别排名，RRF按名次融合。缺席一个列表不贡献该项；参数与top_k必须记录并在保留集前冻结。

命中键后取其完整可见历史，交给V1 resolver按as_of投影。找键的相似度不能推翻计划、时间、纠错或冲突规则。未知问题保留拒答，不能将任意第一名强制视为答案。

known_at过滤必须发生在文档构建前，否则未来术语会污染当时可知的候选排名。未指定known_at时允许当前知识重建过去，这是既有语义，不宣称当时盲检索。

缓存按模型指纹、键、文本SHA-256和维度验证，并允许同键多快照并存。不同provider/model即便维度相同也不能混算。search只使用完整匹配的缓存；缺失或过期明确要求index，不隐式补算全部文档向量。

## 取舍与影响

小规模向量使用标准库计算，不引入NumPy或专用服务；大规模性能尚未验证。按键合并历史更利于保留状态规则，但长历史文档可能增加模型输入开销；本阶段须记录实际规模，不能无条件截断后宣称历史完整。

API配置分离chat与embedding；单个DeepSeek聊天key不被当作embedding服务。无向量服务时可显式跑lexical和离线协议回放，报告分别标记。

## 迁移与回滚

新增memory_vectors缓存，不修改events。更换模型/文档构造方式后重新index，旧缓存可保留供审计但不混用。停用混合检索可退回精确查询或显式lexical模式，事实账本不丢失；旧程序数据库回滚仍遵循ADR0007。

## 验证

用人工标准事件跳过提取，独立测事实键Recall@K、排名、错误拒答、项目串用、known_at快照和重启缓存。旧计划/历史事件不能抢当前答案。协议测试用录制向量只是test double，真实语义召回需真实模型数据验证。

向量接口依据：2026-10-27查阅 [OpenAI Embeddings guide](https://developers.openai.com/api/docs/guides/embeddings) 与 [Embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create)。
