# 阶段目标

让 Agent 从可恢复的模型输出错误中继续时，仍能收到与当前回合预算和公开工具状态相符的提醒。

## 原因与变更

此前工具正常返回后才调用收尾提醒。模型输出在 JSON 解析或动作 schema 校验中失败时，Agent 会发送诊断并提前进入下一轮。原 V3 的 hold-samples 在第 4 回合走过这个分支，余下两轮却没有收到预算提醒。

这次复用同一条反馈组装路径，通过显式策略开关让可恢复的 ValueError 家族也走提醒逻辑。剩余回合数仍按已调用的次数计算。提醒根据已记录的公开工具状态判断，最后一次写入之后须有成功测试与非空 diff 才建议 finish。网络错误继续走终止分支，下一次模型调用不会发生。

## 替代方案与取舍

把预算提示放进固定系统提示更简单，但不会随错误与实际进度变化。直接增加回合能容纳更多修复，也会改变成本上限。自动 finish 会改变严格完成的含义，无法和旧基线公平比较。采用恢复反馈可以单独验证这次漏发问题，同时保留人工和模型可审计的停止条件。

保留公开诊断会占少量上下文空间。静态建议也可能被模型忽略。故障复现测试验证提醒确实送达，独立任务用于测量策略整体的真实表现。

## 兼容、迁移和回滚

仅协议版本 2 的候选开启错误分支提醒。原先的 reference、guided 与组合仍可通过原 V3 协议运行。新实现摘要会使旧试验锁无法在当前实现上继续验证，复查旧结果使用原报告，复跑旧锁使用原提交的程序。旧数据与 SQLite 无需迁移。回到 V2.1 发布版或原 V3 预览提交即可回滚整个程序。
