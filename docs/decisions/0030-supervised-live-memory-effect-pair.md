# 阶段目标

为 V4.4.1 原双组流程增加可审核、有界且保留首次证据的真实模型执行，核对单案例开发结果和实际用量。确认前只有离线证据。

## 原方案与变更原因

V4.4 的 ReplayAgentProvider 固定执行参考动作，只能验证工具链。直接换成旧 LiveAgentProvider 不足以满足本轮：它没有整个组的墙钟上限，异常日志主要在函数返回时保存，缺少配对级模型标识与实际 usage 完整性核验。

新增 memory_effect_live.py，旧 memory_effect.py、有限动作循环、权限、测试与沙箱代码均不变。新 freeze-live 复制旧冻结输入的字节，重绑定执行代码并生成 schema 2。task、as_of、记忆、源码、公开检查、独立检查和参考动作完全相同；不重新召回事实，不根据模型结果重写检查。

当前官方模型名单为 deepseek-flash/deepseek-v4-pro，V4.4 只是拟用 deepseek-chat，尚无旧真实结果可延续；本轮显式选择已配置且官方列出的 deepseek-flash，不在失败后静默换模型。[官方 Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) · [模型说明](https://api-docs.deepseek.com/quick_start/pricing/)，2026-11-16 核对。具体服务和请求体重新供用户确认。

## 选型与原理

使用标准库 subprocess 的独立组进程。协调进程从创建组进程起计时，300 秒内覆盖初始化、HTTP、开发工具和最终评分；超时结束该组进程，不开始下一组。worker 另有 300 秒计时器，防止协调进程被外部关闭后无限请求。安全清理在停止之后单列，不伪称所有清理也能在 300 秒内完成。

HTTP 复用现有无代理、禁止重定向的 OpenAICompatibleProvider；本轮固定官方 HTTPS 地址，凭据只读本机 .env/环境变量，不继承其他模型、网关或超大请求配置。每组最多 6 请求、每请求最多 2048 输出 Token、60 秒网络超时；整个进程上限还能终止慢速持续响应。即使服务端在本地停止后继续计费，缺失 usage 仍是未知。动作仍是原 6 回合/20 动作/3 次代理测试/24000 字符上下文，不赠送处理组额度。格式、截断和传输错误都停止，不自动重试。

每次请求在发出前以独占文件保存 starts；收到响应后保存独立 ends，记录原内容、finish_reason、返回模型、指纹和 usage，不保存推理正文、认证头或上游错误正文。工具读写和容器名称也先留档。report.json 是可原子替换的进度投影，first-start.json 和 final-report.json 不覆盖，原 starts/ends 不改写。中断后能看到已发请求；没有 ends 或损坏的 ends 不被当作零 Token。

usage 校验非 bool 非负整数，total 等于 prompt+completion，缓存命中不得超出输入。缓存是输入子集，不重复求和。任一请求缺失或矛盾，组总用量保持未知。返回模型 ID 需存在且在组内稳定，第二组沿用第一组返回 ID 作检查；指纹冲突也令配对不可判定。返回 ID 一样不能保证服务商永远没有内部升级，结论仍限定于本次观察。

受控容器继续禁网、非 root、只读挂载和固定测试命令。协调进程通过该运行事先记录的随机名称与 owner 标签清理自己的容器，保留清理回执。没有授予模型 shell、安装、隐藏测试或整个仓库读取权限。独立评分只在模型结束后运行，结果不进入后续请求。

## 替代方案与取舍

只用 socket timeout 不能限制持续返回少量字节的响应，也不能限制整个开发过程；仅用线程难以可靠停止阻塞调用。改写旧有限循环会让 V4.4 绑定实现失效，并扩大历史回归范围，因此以外层进程监管、工具日志代理和新 provider 适配。没有新框架、服务队列、SQLite 表或浏览器直接调用模型的能力。

validate-live 使用相同 worker/预算/循环/容器/评分但返回本地参考动作；不会构造 HTTP client，模型请求数为 0，模拟回合另列。这是协议和容器验收，不是模型质量或真实 Token 的证据。单元测试中的虚拟 Token 仅测试判定分支，不混入真实报告。

## 兼容、迁移与回滚

新 CLI 添加 freeze-live、validate-live、live、recover，旧 freeze/offline/view 和旧输入仍可用。SQLite 和正式审核规则不变，无数据迁移，reference 不变。只读页面兼容旧报告，并增加返回标识、请求用量和方向显示。

live 要求明确提供当前 outbound-review.json 的 SHA-256；这绑定发送清单，不是软件能替代人的授权证明。代理必须先取得用户确认。运行目录必须全新，没有自动补跑。协调进程被硬关闭时先核对 worker PID、停止其进程或等待独立上限，再显式 --worker-stopped recover；该选项是人工确认，不能用来假定仍运行的请求已停止。recover 从不调用模型。

回滚停止新 8773 只读查看服务，切回 v4.4.0-design；不终止用户要求保留的 8768，不改数据库。保留 data/v4.4.1 和全部实验目录，旧实现忽略新 schema；要重新执行用匹配代码或另建输入版本，不能覆盖旧成绩。
