# 阶段目标：V2 用有限动作循环连接模型、工具和经验，保持来源可解释

2026-10-28，接受。V1.1只提取事实，V1.2只比较检索；V2增加真实文件修改与测试反馈，所以需要明确的“模型建议→schema校验→权限校验→执行→反馈→停止”循环。

沿用已有DeepSeek HTTP传输和JSON Object模式，新增独立Agent适配器，不改变事实提取提示词。每轮最多4个动作；finish独占一轮动作批次；最多6个模型回合、3次公开pytest调用和20个动作。路径、命令、执行权限在可信工具层决定，模型JSON不能扩权。错误schema返回有限诊断供下一轮修正；传输失败停止该任务，不盲目重试付费请求。上下文有硬上限，超过即停止，不在本阶段开发分层上下文优化。

没有引入LangChain/LangGraph或外部Agent SDK。原生function calling也是合理替代，但现有JSON适配已真实连通、动作集合小，显式schema分派能重用计量和错误处理。该实现是实际执行工具的有限Agent，不是把“模型声称完成”当成功；最终公开/隐藏pytest由可信调度器评分。JSON格式保证不代表动作语义、权限或源码正确。

新增单独SQLite经验表，不迁移核心事件表。经验只在最终验收通过后写入：项目、任务、分类、顺序、来源run及Agent公开交互总结。隐藏测试内容/错误详情不写入经验、不反馈同任务模型。读取同项目、同run中更早成功任务；同类优先，其余取最近经验，最多3条。dev/holdout不共享经验。总结属于不可信上下文，不具备工具权限。

模型请求计数及响应usage直接来自服务，消息历史在每次请求时深拷贝，避免把后续工具结果倒填成先前模型输入。缺失usage保持未知。Langfuse只重放已完成任务，沿用V1.2标准token字段及只读核验机制，不把export回放再次算模型推理。

回滚可停用agent命令，保留新经验库/报告/任务副本。旧import/query/ingest/search/compare和历史证据保留；不引入V2.1的OpenViking或V3的策略搜索。

依据：[DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。真实模型表现必须另测，人工动作回放只能验协议和工具。
