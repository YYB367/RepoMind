# 阶段目标

让浏览器审核与命令行、Codex 使用同一项目记忆及审核规则，并能在独立会话中核对事实与来源。

# ADR 0025：本机 HTTP 工作台复用审核与时间投影

状态：V4.1 采用。

## 原方案与新增需求

V3.1 已有 ReviewQueue 的提议、修改、确认、拒绝，以及原子事件写入。V4.0 的显式 Codex 包装器从同库召回已确认事实。此前全部依赖命令行；本版需要两个浏览器页面管理这些记录。领域规则和 SQLite 数据格式已有回归证据，新增页面应直接调用这些能力。

## 选型与替代方案

采用 Python 标准库 ThreadingHTTPServer、静态 HTML/CSS/JavaScript，以及现有 Pydantic 校验。用途限定在单机、两个页面、JSON 请求；无 Node 构建、CDN、字体下载或新增运行依赖。每个请求使用独立 SQLite 连接，避免在线程间共享连接。查询用只读连接与读事务；确认仍使用 ReviewQueue 的 BEGIN IMMEDIATE。

比较过 FastAPI/Flask：路由和错误处理中间件更成熟，适合后续身份认证和多人服务，但本轮引入框架、ASGI/WSGI 启动器及版本维护并不能改善单机审核规则。比较过 React/Vue：组件化适合复杂编辑器，但两个页面的表单、列表与详情可以由浏览器原生 DOM 完成；当前选型省去打包工具和前后端两套依赖管理。Streamlit 能更快做数据展示，但交互重新执行、页面导航和精确的审核版本控制需要额外处理。

SQLite 继续适合单机持久化。事务将正式事件、引文、来源关系和候选状态一起提交；失败全部回滚。浏览器提交项目、候选 ID 和 revision，版本不一致返回 409，让用户刷新并重新核对。确认和拒绝的同决策重试保持幂等；终态不能反转。网页不提供直接导入正式事件的接口。

## 查询和来源原理

Workbench 按项目读取正式事件，按 subject / predicate 分组，把事实日期和获知日期交给同一个 MemoryResolver。计划不冒充完成事实，冲突显示证据不足。搜索是名称和结果内容的大小写无关子串筛选；不调用 Embedding 或 LLM，也不代表语义检索质量改善。UTC 日期取当天结束，可用获知日期重现确认前系统不知道这条事实的状态。

来源只展示已持久化的引文、路径、文件摘要、Git 提交及时间。浏览器通过 textContent 显示数据，不把来源当 HTML 执行，也不开放任意宿主文件下载。Git 来源可以在原提交复核；文件来源路径可能失效，原始引文与摘要仍保留，完整原文件应另行归档。

## 本机边界和错误处理

固定监听 127.0.0.1，严格检查带端口的 Host；写操作还要求同源 Origin 和页面随机令牌。设置内容类型、禁止外部脚本/页面嵌入和缓存的响应头；限制 JSON 请求大小及读取时间。该服务没有多用户身份和远程访问设计。标准库服务适用于这个本机工作台；公开部署应另立阶段设计认证、TLS、反向代理及运维。

空库只读查询不创建数据库。输入错误保留当前修改；版本冲突清空过期详情并要求重查。查询序号避免较慢响应覆盖新查询；已展示记录的项目绑定在该批结果上，编辑筛选框尚未查询时不会改变记录所属项目。

## 兼容、迁移与回滚

新增 web 命令与打包的静态资源，原 CLI、Codex 包装器及事件 schema 不变。ReviewQueue 增加默认开启的 initialize 参数，工作台读请求用 initialize=False 读取已存在审核表。SQLite user_version 仍为 2，无数据迁移、复制或删除。

实际试点继续使用 work/v4.0/pilot.sqlite3；第一次准备时通过 SQLite backup 创建 work/v4.1/pilot-before.sqlite3，保留初始 V4.0 状态。回滚只需停掉 web 服务，使用 v4.0.0 或 v3.1.0 的 CLI 读同库。已确认记录是兼容事件，不需要撤销。若为完全独立的回放需要恢复初始试点，停掉所有写入进程后，把备份复制成一个新库并显式指定 --db；保留现库和审核证据。不要覆盖正在使用的库。

## 验证与限制

HTTP 集成测试验证共享规则、过期版本、拒绝与项目隔离、来源、计划/冲突、双时间、分页、空库和同源限制。浏览器在隔离库验证错误恢复、拒绝、引文 HTML 不执行与手机布局。真实试点用 Git 记录生成候选，在网页编辑到第 2 版，由用户明确批准后点击确认；独立 CLI 读回后，新 codex exec 会话自动得到事实与来源。V4.0 原生 hooks 仍没有新的真实触发证据，本版会话验收沿用显式包装器。

## V4.3 补充：公共分页参数契约

本次目标：强化 `workbench.page` 的参数校验，保持合法空页、总数和 HTTP 分页兼容；不扩展阶段范围。

原实现直接使用 Python 切片，只有 HTTP 层检查分页范围。直接调用公共函数时，负偏移会从末尾取值，bool 被视为整数，非法 limit 可能返回空页或突破 100 条上限，其他类型则产生不统一的 TypeError。

采用公共函数入口的显式类型与范围检查：offset 必须为非 bool 的非负整数；limit 必须为非 bool 的 1 到 100 整数，否则抛出 ValueError。Python 的 bool 是 int 子类，因此必须单独排除。检查放在切片前，空列表也遵循相同契约；合法输入继续使用原切片与 len(rows)，越过末尾仍返回空 items 和未分页总数。这适合当前复用服务函数的本机工作台，无需新增依赖。

比较了仅保留 HTTP 校验、自动 int 转换与截断越界值：前者遗漏直接调用，后两者会掩盖调用错误并接受 bool 或小数。保留 HTTP 层现有字符串解析及错误响应，在公共函数拒绝不合法的调用参数；不改动 HTTP 默认 offset=0、limit=50、范围和 400 错误文案。

兼容影响仅限此前意外接受的非法公共函数输入；合法返回结构、候选 counts、时间投影和数据库格式不变，无数据迁移。回滚可移除 page 新增校验及对应回归测试，无需恢复或改写数据库，保留旧报告与冻结数据。

验证使用 `tests/test_workbench.py` 的直接函数回归和本机 HTTP 协议测试：覆盖负数、bool、浮点、字符串、None、limit 上下界、空输入、末尾及超出末尾、总数和输入列表保持不变。新增直接函数测试在修复前为 17 失败、6 通过，证明可重现缺口。使用指定的 `work/v2-venv/Scripts/python.exe` 执行 `-m pytest tests/test_workbench.py -q`，修复后 35 项全部通过。测试只使用内存列表或隔离临时数据库，不涉及真实模型调用，不能推导模型质量或成本结论。
