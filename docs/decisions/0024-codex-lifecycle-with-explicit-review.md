# 阶段目标

让独立 Codex 会话复用同项目已经确认的记忆，并在任务结束时把可追溯的新事实送入原审核队列。

## 接入方式和原理

OpenAI 官方文档给出了项目内的 SessionStart、UserPromptSubmit 和 Stop hooks。会话启动时提供一份简短的提交约定。提交任务时用任务文本匹配同项目的已确认事件，经过原双时间解析后返回事实与来源。任务结束时只解析最终回复末尾专用的结构化块。Codex 负责触发事件，RepoMind 负责证据验证、去重与审核。[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)

保留显式 codex exec 包装器。它读取同一个库并把相关记忆交给新会话，等待 Codex 报告任务完成后提取最终回复并生成候选。此路径每个会话由调用者启动，适合项目 hooks 尚未启用或尚未完成信任检查的环境。

候选引用限定为项目内可审核记录，核对逐字引文和记录摘要。完整会话、密码文件和日志都不用于自动写入。召回结果按项目和任务词匹配，只读数据库，输出限制为四条与 3200 个 JSON UTF-8 字节。来源和事实作为数据交给模型。确认沿用 V3.1 的 revision 校验和单库事务。

## 取舍、兼容和回滚

全量读取会话转录可以提取更多细节，也会增加隐私、上下文与格式兼容成本。采用最终回复中的显式块，让模型整理完成项，并用原文校验和人类审核限制错误。模型省略块或资料不在许可范围时，操作者可用 V3.1 CLI 补录。词匹配可复现且无需额外服务，改写或同义词召回仍有限。

未引入新数据库 schema。生成器不会覆盖已有 hooks 文件。需要启用原生路径时，生成项目本地定义并使用 Codex 自身的审核流程。退出使用时禁用该项目的三个 hooks 或停止使用包装器，V3.1 审核与已确认事件仍可查询。
