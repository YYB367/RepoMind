# 阶段目标：让 V1.2 质量、延迟、usage与成本比较具备明确分母和归属

ADR0013；状态：接受；日期：2026-10-27；范围V1.2。

## 原方案与触发原因

V1.1测自研单流程；V1.2增加多个provider与平台同步。若把共享准备重复计入、把缓存0请求视为免费服务，或将未知缓存token全部按最低价计算，成本与速度比较会误导。

## 替代方案比较

| 方案 | 问题/收益 | 取舍 |
|---|---|---|
| 按字符数猜token再乘网上价格 | 容易出数字 | 与实际usage、地区、币种和缓存价可能不符；不采用 |
| 默认没有usage/价卡即费用0 | 表格整齐 | 把未知伪装免费；不采用 |
| 共享缓存向量后称某后端低token | 减少API调用 | 混淆准备与后端改进；不采用该结论 |
| 独立live client+实报usage+价卡可选 | 可追查真实调用与测量缺失 | 采用；实际会发生多份Embedding调用 |
| offline同向量bytes单列 | 更好控制协议与排名 | 采用；只测工程管线，不测真实语义或价格 |

## 决策与指标

质量分别报告完整查询准确率、已知键Recall@K、未知拒答、来源与项目隔离、失败样例及分母。no_memory无证据按同样金标评分；hybrid独立列，不将策略增强误算成后端优势。

计时拆为公共准备、variant索引/查询/resolver和平台同步；记录样本、运行顺序、冷/热与并发。小样本分位数按实际定义报告，不做生产延迟保证。

live每variant独立Embedding client，记录实际请求数、服务usage、输入/输出hash与fingerprint。同样输入若服务返回不同向量，报告差异flag；不宣称完全固定逐bit条件。共享准备只记一次shared preparation，实际重复的模型请求则分别归属调用方，不能同时算进共享与variant。

## 价卡与原理

默认cost=null，费用未测。仅显式pricing价卡明确模型、币种、计价单位和有效范围时，按实际usage估算；估算不是账单证明。输入、缓存输入和输出类别互斥；若总输入已含缓存，要先按已知拆分，不能重复相加。

若缺价卡、usage或缓存token分类，记录缺失原因，不能猜免费、币种或最低缓存价。offline没有API调用可记录0实际调用/token及real_cost_verified=false，不能由此推出某后端在真实服务中“零成本”。本轮不增加shared_live第三模式。

## 影响、迁移与回滚

新报告增加配置、usage来源、归属、缺失状态与可选估算字段，不改事件schema或旧V1/V1.1报告。价卡变更仅生成新估算版本，保留原报告和价卡hash，不回写过去成本。

回滚可移除pricing配置，cost回到null，真实usage仍保存。不得为让表格完整编造token，也不将Langfuse重放传输再记成原模型推理。验证覆盖无价卡、缺usage、缓存分类缺失、明确价卡计算、重复归属与offline/live标签。
