# 阶段目标：安全扩展 V1.1 存储，并分离提取、检索和端到端验收

ADR 0007；状态：接受；日期：2026-10-27；范围：V1.1。

## 原方案与触发原因

V1 schema1只存事件及原始JSON，评测主要覆盖规则检索与状态投影。新增自然语言入口后，需要保留来源原文、片段和提取配置；新增Embedding后，需要持久化可验证的向量快照。新增错误来源也使单一总分不足以归因。

## 替代方案比较

| 方案 | 问题或收益 | 决策 |
|---|---|---|
| 直接在events覆盖内容或塞入模型字段 | 会混淆原始事实与派生数据，并提高回滚风险 | 不采用 |
| 独立JSON/向量文件 | 简单，但跨文件来源/事件/引文难以统一回滚 | 不作为主存储 |
| SQLite增表与事务迁移 | 保留账本，统一完整性边界 | 采用schema2 |
| 只做端到端评测 | 无法分辨提取错、找键错还是投影错 | 不采用，分阶段测量 |
| 仅用录制响应宣布智能效果 | 无法证明真实模型理解或语义质量 | 不采用；test double与live报告分开 |

## 决策与原理

schema1→2采用增量迁移：保留events表及内容，新增nl_sources、extraction_provenance、memory_vectors；迁移置于事务，失败回滚，未知版本拒绝打开。来源、事件与引文的apply也处于同一事务，禁止半写入。

保留原V1测试、fixture与报告。新增V1.1开发/保留数据、人工独立标准答案和文件hash；分别测：提取（固定原文）、检索（固定人工事件）和端到端。报告包含配置、模型身份、时间、失败阶段、来源与项目范围，并保存首次保留结果。

离线录制响应和向量只验证工程契约，标test double；live运行单列，真实模型未配置时注明待验收，不将离线分数冒称语义能力。服务usage缺失就报告缺失，不编造Token、成本或价格。

## 取舍与影响

增表增加schema版本和迁移测试；换来旧事件稳定以及可重放来源。公开新保留集后不能在未来继续当作盲测，需追加独立数据。分阶段评测维护成本更高，但错误可定位，避免用模型错误掩盖规则退化。

## 迁移步骤

1. 停止写入，记录schema1事件数量及内容摘要。
2. 关闭连接后备份数据库，或使用SQLite backup API生成一致性备份；活动写入时不得仅复制主文件。
3. 使用新版本开启库，在一个事务中创建新表和版本标记。
4. 验证旧事件不变、新表存在、重开幂等，运行旧规则与新迁移回归。
5. 保留备份、迁移记录和新版本验收结果。

## 回滚

旧V1二进制拒绝schema2，因此仅回退代码不能恢复旧环境。保留schema2库，再恢复升级前schema1备份并使用原版本；升级后新增数据需另行审计迁移，不能假定自动保留。本阶段不提供自动降级，不允许只改PRAGMA user_version欺骗版本检查。

## 验证

迁移成功、幂等、失败回滚及旧内容不变；原子apply；重启后来源/引文/向量可读；失效快照不能使用。原V1核心回归全过，项目串用0；全部失败公开，效果阈值在真实模型和新数据冻结时预先规定。
