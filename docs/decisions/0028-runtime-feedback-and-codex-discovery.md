# 阶段目标

收尾 V4.3.1 的 Codex 程序路径、运行可见性和失败反馈问题，保留真实试用的原始结果与用户审核边界。

# ADR 0028：统一程序发现、流式执行事件与独立活动表

状态：V4.3.1 采用。

## 原方案、问题与选择

V4.3 用裸 codex 命令启动子进程，并在 communicate 完成后解析全部结果。Desktop 升级可能替换带构建号的程序目录，旧 PATH 或服务进程继承的环境因此失效；预查又把程序启动问题混成登录失败。已有本地修复尚未提交，本版核对并收纳，而非覆盖重写。统一 resolver 依次读取显式绝对路径、PATH 和 Windows Desktop 安装候选；每次调用重新解析，不缓存构建号。显式路径无效时立即报错，避免悄悄改用别的程序。Desktop fallback 按程序修改时间选择，安装布局不是官方稳定接口，需要预查实际启动结果。

旧版只在完成后保存工具退出码，长任务没有活动信息，也无法判断后续成功是否覆盖了首次失败。沿用 Python 子进程与现有 HTTP 服务，两个读取线程并行排空 stdout/stderr，主循环逐行消费 Codex JSONL 并检查超时/停止。使用有界队列防止读取无限堆积；独立写入线程避免大输入与子进程输出互相等待。模型推理文本不进入活动日志。

官方非交互文档描述了 JSONL 的 item.started、item.completed 和 command_execution；本项目只取命令、状态、退出码与输出摘录，并保存本机时间。具体包版本和本机运行能力用实际无模型预查核对。[官方文档](https://learn.chatgpt.com/docs/non-interactive-mode)

比较过 WebSocket、另建任务队列和读取 Codex 私有聊天日志。当前单机串行场景继续用原 1.5 秒轮询与 SQLite，避免引入额外服务，也不依赖私有历史格式。旧任务没有保存的字段明确未知，不扫描其他聊天来拼凑证据。

## 持久化与失败解释

新增 web_task_activity 表按任务保存脱敏事件，原 web_tasks.receipt 不需要回填。读取时组合状态、时间和活动视图；跨项目仍先核对任务所属项目。进程检查每两秒记录一次，不更新最近活动时间；两者代表不同证据。浏览器每秒刷新运行时间，结束时间存在时固定。

命令启动和结束事件保留在事件序列中，失败不被后续记录覆盖。根据去首尾空白前后的完整命令摘要及事件顺序派生“后续同命令”关系；已经并行启动的调用不算后续重试。它是关系推定，不证明助手的语义意图；改写命令、环境变化和因果关联无法由此认定。缺失退出码的 failed 命令仍保留原因。Codex 主进程非零退出也记录为独立失败，不能用内部某条命令成功代替整体执行成功。

正文先经过进程环境中已配置的凭据值替换，再清理常见 key/token/password 赋值、授权头、Cookie、带认证的 URL 和控制字符，最后截断。不保存未脱敏命令副本或模型思考；签名只用于同任务匹配。日志和 DOM 都把文字当数据，不执行预览中的命令。任意私人自然语言、启动服务后才注入的秘密及未知格式不能完全识别，因此仍须避免在需求与命令写入秘密。

单行 JSONL 上限 1 MiB、子进程输出累计 16 MiB，超过后停止并保留已保存记录。活动命令事件最多 2000 条，超限计数提示不完整；每条命令/输出最多 8000 字符，原因取已保存失败输出末 2000 字符。保存范围有限，不能宣称保留完整终端流。

## 兼容、迁移和回滚

SQLite user_version 仍为 2；web_task_activity 为按需新增表，不改正式记忆、候选审核和 reference 策略。旧版忽略新表；旧任务读取时生成带 legacy 标记的视图，不改原 JSON。已有来源快照仍以原摘要读取，即使日常指南后来修订也保留原证据。

回滚先停止工作台和在跑的任务，核对残留子进程及文件，再切回 v4.3.0 并启动原服务。活动表可以保留，无需删表或覆盖数据库；旧版不会展示新反馈，原路径问题也可能重现。若只回滚界面可恢复 tasks.js/style.css；不要删除原始失败事件来“修复”显示。异常退出不自动重跑，仍需人工核对遗留 Codex 子进程。
