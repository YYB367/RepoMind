# 阶段目标

从真实 RepoMind 试点提名有限候选，以新维护任务和两轮独立验证补验 V3 策略门槛，保留首次数据及结果。

# ADR 0026：冻结试点上下文和新任务，限制候选的变动范围

状态：V4.2 采用。

## 问题与原方案

V3 的开发题曾显示收尾提示有利，但原保留两轮未复现同类改善；恢复提醒加压缩同样未通过门槛。继续反复使用旧保留题会让保留结果进入调优，无法作为新证据。V4.1 真实会话回执还显示，明确查询 codex.v4_acceptance_path 会携带共享 acceptance 词的另一条 harness 事实。这条来源正确的额外记忆构成上下文冗余，而非事实错误。

## 决策及原理

使用原 finite Agent、JSON 动作协议、Docker 判题及 V3 评分函数，新增协议 3。提名只读取摘要固定的 V4.1 真实会话回执，不在提名阶段再调用模型。把该会话实际收到的两条已确认记忆冻结为快照，保留 source_id、path、commit 和 sha256。所有方案先拿到同一快照；focused-evidence 只对任务显式声明的 subject / field 键作精确筛选，focused-evidence-compact 再复用旧 write_file 历史正文压缩。无显式键则保留完整快照。

reference 的循环、提示和工具权限保持原实现；它在本轮收到完整真实快照。候选不修改回答来源，不进行猜测性语义筛选，不增加动作或回合。实际写入内容、测试结果和 Git diff 留在工具轨迹里；历史压缩只影响后续模型输入。因子只有明确键筛选和写入历史压缩，未加入收尾提示以免把多种变化混在一起。

比较过直接升级 Embedding、增加模型预算、修改 Codex 原生集成和继续调旧保留题。Embedding 会引入另一模型和召回质量变化；扩预算改变比较条件；原生 Codex 受当前工具沙箱限制且控制参数与 V3 不同；旧题已失去新保留证据的作用。因此选择有限可审计的输入变动和新的维护情景。选择锁绑定实现、完整协议、提示、模型配置、镜像及开发报告摘要，验证启动时先核对锁再打开保留任务。

## 新任务与真实性边界

新任务为明确键解析、来源展示和日期缺省的三个开发题，以及审核请求、证据字节预算、确认日期窗口、SQLite 来源授权的四个保留题。使用 v4.1.0 核心源码工作副本，加上待实现的维护 helper；不自动把实验补丁合并进产品。任务来自真实功能与观测到的问题，由本轮实现者构造，属于项目派生的受控维护题，不是第三方盲测、完整生产任务或 Codex 日常开发效果测量。开发与保留实现目标不同，也未复用 V3/RelayBox 题目。

构造期首次参考动作检查暴露句末句号的参考解析器错误。原初稿及其回执保存在 data/v4.2-authoring-v1 与 reports/v4.2/authoring-*，正式 data/v4.2 修正参考实现，评分要求不降低。这一修订发生在任何新真实模型调用之前。正式冻结后不因模型保留结果更改题目、候选或门槛。

## 依赖、预算和失败处理

原镜像只有 pytest，不能导入 RepoMind 的 Pydantic 模型。派生镜像固定使用与本机相同的 Pydantic 及四个依赖，继承原测试 runner，运行时仍禁网、非 root、只读和限额；两个比较方案使用同一不可变镜像 ID。旧镜像及旧报告不变。Docker 构建使用本地别名定位原镜像，运行仍记录并校验最终镜像 ID。

开发最多 54 次、两轮保留最多 96 次聊天请求，合计 150 次；不额外预热或自动补跑。每项任务 6 回合、20 动作、3 次公开测试、24K 字符上下文，响应 2048 Token。实际温度、服务配置和返回的模型标识进入证据。传输或沙箱工程错误发生后写出已结束任务并停止该实验，保留部分证据，不把它们当候选质量失败，也不自动重启覆盖。

严格完成及代码通过均不得下降。开发集与两轮保留都须通过，保留两轮须同类改善；质量持平时每轮至少节省 10% 总 Token。用量不完整、模型标识不一致或工程失败都不能晋升。摘要总 Token 包含服务实际报告的输入和输出，不以缓存折价或美元估算替代该门槛。金额没有结算证据则保持未知。

## 兼容、迁移与回滚

不改 SQLite schema、审核规则、工作台或 Codex 默认召回；协议 1/2 继续选择原候选集合。新策略仅在协议 3 实验中可选，即使结果支持推荐，也不静默改变日常 reference 默认配置。无需数据迁移。回滚使用 v4.1.0 并停止新实验，保留 data/v4.2、选择锁和首次报告。旧镜像可继续跑旧测试，新镜像无需删除。
