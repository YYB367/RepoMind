# 阶段目标

让每次交付既可以运行和验收，也能帮助维护者理解设计理由、技术原理及变更的后果。此规范从 V1.1 开始适用，原 V1 历史报告保持原貌。

## 交付说明的固定顺序

1. 本阶段目标、输入、输出和明确版本边界。
2. 已完成能力和实际运行方式。
3. 技术选择：解决什么问题、为什么现在采用、基本原理、本项目调用路径、限制。
4. 技术变更：原方案、触发原因、候选比较、最终取舍、兼容影响、迁移/回滚、验证。
5. 文件变更和可追溯的 ADR。
6. 实际测试结果、使用的输入/配置、失败项与修复记录。
7. 尚未解决的问题、未验证的结论和下一阶段建议。

每个技术说明至少有一个本项目例子。公式先解释直觉再解释变量；不得把格式正确等同于事实正确，把测试替身等同于真实模型，把小样本通过等同于生产可靠性。

技术变更应说明对用户命令、依赖、数据库、已保存记忆和报告的具体影响。需要重建索引时解释原因；不能让用户猜测为什么旧缓存失效。
