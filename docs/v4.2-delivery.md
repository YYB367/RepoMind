## 交付结论与运行方法

**工程与实验流程验收完成；策略晋升未通过，继续使用 reference。** 锁定候选 focused-evidence 在两轮新保留集均提高严格完成数，但开发集质量持平、总 Token 仅降低 7.02%，没有满足沿用的完整晋升规则所要求的开发集改善门槛。不能因为保留结果较好而在事后删除该条件。

在仓库根目录执行，使用本工作区现有环境：

~~~powershell
Set-Location 'D:/software/codex/2026-10-26/1-repomind-codex-md-2-repomind/outputs/RepoMind'
$python = '../../work/v2-venv/Scripts/python.exe'
$env:PYTHONPATH = 'src'
$image = 'sha256:bc6c2f2343c2855ee369fe9b20f5b834350eab234b96d14e48ec5e0038d0eb97'
$common = @('--suite','data/v4.2','--history','reports/v4.1/new-session.json','--run-dir','work/v4.2-recheck','--image',$image,'--config-dir','../../work/docker-v2-config')
& $python -m repomind harness-tune @common
& $python -m repomind harness-validate @common
~~~

默认命令使用人工参考动作，不调用模型。真实比较需要现有 .env 的聊天配置，在两条命令分别增加 --live，并使用新的独立目录。会产生新的模型使用量；现有 work/v4.2-live 和已导出首次报告拒绝覆盖。本轮授权范围、发送内容和 150 次请求上限已归档，不自动追加或补跑。

本机正式试验在 work/v4.2-live；人工参考回放在 work/v4.2-replay。阶段报告可通过 scripts/export_v42_run.py 导出，分析脚本 scripts/analyze_v42.py 只分析既有回执，不重新调用模型。它默认写入 reports/v4.2 的新文件，已有文件时拒绝覆盖。

~~~powershell

docker image inspect repomind-v42-pytest --format '{{.Id}}'
~~~

启动实验前须与冻结的 $image 核对。wheel 只含程序与网页资源，复现实验还需要源码包中的 data 和报告。

## 技术选型与工作原理

试点的实际 new-session.json 显示，询问 codex.v4_acceptance_path 时，词匹配还携带另一条共享 acceptance 词的 harness 事实。两条都已确认且来源正确，但后一条与明确查询键无关。以该实际回执作提名证据，比增加一批猜测性的策略更便于审计。[试点原回执](../reports/v4.1/new-session.json)

reference 使用原有限 Agent 循环和两条事实的完整快照。focused-evidence 按每题事先声明的 subject / field 精确保留一条事实，连同 source_id、path、commit、sha256 一起传入。focused-evidence-compact 再复用原写入历史压缩；实际工具动作及完整响应仍记在轨迹中。任务没有明确键时不会猜测删减。三个方案使用同一来源快照、动作权限、基础提示、模型配置和预算。

采用原 Python/JSON/Docker 管线，便于把本轮数据和旧门槛直接对照。没有增加 Embedding 模型、训练流程、云端评测平台或自动策略部署。字节摘要锁住输入与实现，SQLite 已确认事实只读导出为快照；实验产生的代码修改发生在隔离副本，不合并到产品，也不自动写入正式记忆。

原测试镜像只含 pytest，不能导入实际 RepoMind 的 Pydantic 模型。本版在原固定镜像上增加 Pydantic 2.14.1、pydantic-core 2.50.1、annotated-types 0.8.0、typing-extensions 4.16.0 和 typing-inspection 0.4.4，与本机版本相同。运行仍为无网络、非 root、只读挂载、256 MiB / 1 CPU / 64 PID，两个方案共用同一镜像。模型网络请求由宿主的既有传输发送，密钥不进入镜像。

比较过增加预算、升级语义检索、调整 Codex 集成和复用旧保留题。它们会引入新的混杂因素或利用已看过的结果，本轮选择精确键与已有压缩，保持变化有限。技术比较、具体取舍及兼容影响见 [ADR 0026](decisions/0026-pilot-evidence-and-independent-policy-gate.md)。

## 冻结、请求授权与评分

正式输入冻结在提交 **71366dc**，早于所有本轮真实模型调用。冻结记录包含实现、提示、协议、任务清单、镜像、模型配置及预算。开发集只比较三个预先提名的方案，按严格完成、代码通过、总 Token、名称排序，选定 focused-evidence；选择锁随后约束两轮保留验证。结束后再次核对实现和输入摘要，未修改。[冻结记录](../reports/v4.2/freeze.json) · [选择锁](../reports/v4.2/live-selection-lock.json)

每任务仍为 6 回合、20 动作、3 次公开测试、24,000 字符上下文及每响应最多 2,048 Token。开发最多 54 次请求，两轮保留最多 96 次，总上限 150。实际没有额外预热、失败后补跑或超额追加。隐藏测试在该任务结束后评分，不反馈给当前或后续任务模型。

自动审批第一次阻止了外部发送，尚未启动模型进程。随后生成了七个任务的具体发送清单，用户明确回复“授权发送上述数据至 DeepSeek，继续真实验收”后才启动。范围是隔离源码、公开测试、两条已确认事实和执行中生成的工具反馈；没有发送 .env、聊天记录、整个数据库、隐藏测试或参考解答。[具体清单](../reports/v4.2/outbound-review.json) · [用户授权](../reports/v4.2/outbound-approval.json)

严格完成要求公开与隐藏代码验收都通过、有实际改动且正常 finish；代码通过单列。完整原门槛同时要求开发集先有合格改善，再要求两轮保留均不降低严格完成及代码通过，并复现同类改善。严格完成增加属于质量改善；质量持平时总输入加输出 Token 至少降低 10%。同一返回模型、完整用量、无工程错误也是必要条件。本轮没有改变旧函数中的开发门槛。

## 失败原因与尚缺证据

六项未严格完成的真实试验均保留：开发集 dev-key 中 reference 和 focused-evidence 将 a.b.c 错识别为 a.b，隐藏边界测试失败；压缩候选的该题隐藏测试通过，但公开测试仍失败，并出现 JSON/schema 协议错误。三者都达到回合上限而未正常 finish。

保留第 1 轮 reference 的 hold-window，以及第 2 轮 reference 的 hold-pack，最终代码测试通过，但协议错误消耗回合，未正常 finish。第 2 轮 reference 的 hold-window 未正确把日期下界转换为 UTC 日初，公开及隐藏要求没有完全满足，同时耗尽回合。[失败细节与判题输出](../reports/v4.2/failures.json)

现有证据支持“这四个新保留任务的两轮严格完成有所改善”，仍缺少“开发集也达到事先声明改善门槛”的证据，因而不支持完整晋升。单次 3 题开发、4 题保留的样本很小；任务由同一实现者构造，两轮复用同四题，不是第三方盲测或生产开发泛化证明。没有在本轮修改条件或补跑来补齐这一缺口。

Codex 原生 hooks 的真实触发、Windows 工具沙箱写入、语义改写召回和可访问性人工复核沿用 V4.1 的遗留项，本版未声称解决。

## 兼容、迁移和回滚

SQLite user_version 仍为 2，无库迁移；日常审核、网页和 Codex 命令继续使用既有库。新协议仅在 data/v4.2 启用，协议 1/2 的候选集合与行为保持原定义。选择锁包含版本和实现摘要，历史运行的锁应由当时实现重现，不能跨版本继续同一冻结运行；新版本重跑须使用新目录并保留旧结果。

回滚应用可切回 v4.1.0，继续读同一记忆库；保留新数据、镜像及报告，无需删表或删除试点记录。新的候选没有部署到日常开发流程，reference 默认配置无需恢复。wheel 在源码目录外安装验证版本、原记忆召回及资源打包；发布包排除密钥和数据库。冻结摘要及历史文件核对见 [发布检查](../reports/v4.2/distribution.json)。

本版停止于 V4.2。工程交付与真实实验已完成，候选按原完整门槛不予晋升。
