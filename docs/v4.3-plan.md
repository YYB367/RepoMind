# 阶段目标

在本地网页完成开发任务、证据预览和记忆审核；以真实 RepoMind 开发任务验证用户不预填事实也能产生候选，确认后独立新会话使用该记忆。

## 实现方案

新增任务页，先预查环境与已确认记忆，用户点击启动后在后台运行原 Codex 包装器的 workspace-write 会话。任务状态、原始结果摘要、修改前后正文及 diff 保存在同一 SQLite 的新增任务表；单进程串行执行，运行中拒绝第二个任务，重启后中断任务不自动重跑。任务只接收项目和开发需求，候选字段由助手根据产出提出。

项目到目录的映射只在本地启动配置中登记，网页不能指定任意宿主路径。源码预览限 Markdown、Python、JSON、文本及 256 KiB；拒绝越界、链接、隐藏/敏感路径。Git 候选读取该提交的 blob；文件候选优先匹配任务结束时的快照摘要，当前文件不同则提示变化。无法取全原文时降级为已保存引文，明确范围。来源读取与编辑表单分离，失败不重建编辑区。

保留既有审核事务、revision、幂等规则与正式账本。新增候选理由为可选字段，旧候选仍可读取。任务关联候选及文件快照，下一任务从同库再次召回；无自动确认。

## 界面

沿用 V4.1 的冷灰 #F3F6FA、纸面 #FFFFFF、正文 #202F43、蓝 #3659C9、绿 #19765E 和系统中文字体。导航新增任务入口。任务页左侧需求与环境/记忆预查，右侧结果、文件差异和候选；审核页事实编辑与来源正文相邻，原文命中用 mark 高亮。窄屏纵向排列。避免把任务状态做成装饰统计卡，把空间留给源码与差异。

## 验收

隔离测试检查任务生命周期、并发和重启，来源匹配、文件变化、缺失、越界、大文件、Git 版本、引用降级，以及审核与召回隔离。浏览器检查错误保留编辑、实际正文高亮和 diff。真实任务的输入只描述开发需求，须产生文件改动与助手候选，经用户批准后在网页确认，再启动独立会话获取事实与来源。不用模拟结果替代真实链路。
