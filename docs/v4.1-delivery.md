# 阶段目标

让用户在本地浏览器审核 V3.1 / V4.0 产生的记忆候选，按项目、内容和日期查询正式记忆。以 RepoMind 自身的真实交付记录，验证网页审核、命令行读回和新 Codex 会话自动召回共用同一记忆库。执行策略继续使用 reference，本版完成后停止。

## 运行方法

在本工作区的仓库根目录执行：

~~~powershell
Set-Location 'D:/software/codex/2026-10-26/1-repomind-codex-md-2-repomind/outputs/RepoMind'
$python = '../../work/v2-venv/Scripts/python.exe'
$env:PYTHONPATH = 'src'
$ledger = 'work/v4.0/pilot.sqlite3'
& $python -m repomind --db $ledger web --project RepoMind --port 8765
~~~

打开 [待确认页](http://127.0.0.1:8765/review) 或 [项目记忆页](http://127.0.0.1:8765/memories)。地址必须使用启动输出中的 127.0.0.1 与端口。按 Ctrl+C 停止；端口被占用时可改为 --port 8768。已安装 wheel 的环境直接运行 repomind --db 库路径 web，不需要 PYTHONPATH。

全新环境用 Python 3.11+ 执行 python -m pip install -e ".[dev]"。本版仅依赖已有的 Pydantic；浏览器静态资源已包含在 wheel 中，无 npm 安装和外部字体。空库打开时显示空记录，不会创建文件；通过既有 review propose 或 Codex 流程生成候选后刷新。

待确认页支持项目、搜索及审核状态筛选，查看引文、路径、Git 提交、SHA-256 和时间。修改事实内容、事件类型或生效时间后先保存，再点击确认或拒绝；最终弹窗展示项目、事实、审核版本和来源。已确认、已拒绝记录保留在审核历史。页面刷新可读到命令行作出的变更。

项目记忆页按项目搜索名称和事实内容，并按事实日期查询当时有效的事实。可选的获知日期限制系统在该日已收到的记录；日期均取 UTC 当日结束。计划显示“仅有计划”，同一生效时间存在不同值时显示“事实冲突”。这些结果复用原时间规则，不会把计划作为实施完成。

命令行与新 Codex 会话使用同一个 --db：

~~~powershell
& $python -m repomind --db $ledger review list --project RepoMind --status confirmed
& $python -m repomind --db $ledger query --project RepoMind --subject codex --field v4_acceptance_path --as-of 2026-11-07 --with-sources
& $python -m repomind --db $ledger codex --root . --project RepoMind run --prompt '根据 codex.v4_acceptance_path 写出后续接入交接，引用来源'
~~~

最后一条会真实启动 Codex 并使用其登录与额度。网页本身不调用模型；Codex 显式包装器仍需手动启动每个新会话。原生 hooks 的安装和信任方法参见 [V4.0 交付](v4.0-delivery.md)。

## 技术选择与工作原理

选用 Python 标准库 HTTP 服务和原生 HTML/CSS/JavaScript，是因为本版只有单机的两个页面，现有规则已在 Python 内。浏览器发 JSON 请求，服务端用 Pydantic 校验字段，再调用原 ReviewQueue；每次请求独立连接 SQLite。这样避免维护第二套审核逻辑或新增前端构建工具。

审核确认由 BEGIN IMMEDIATE 事务串行执行，正式事件、来源引文和审核状态一起提交。请求携带 revision；他人已修改时返回 409 并要求刷新。重复确认相同版本不会多写事件；已拒绝记录不能直接反转为确认。原事务失败回滚规则继续有效。

查询按项目读取正式事件并按事实键分组，通过原 MemoryResolver 按有效时间和获知时间选择证据。计划与冲突有独立状态。搜索采用子串匹配；本版没有替换已有 Embedding 或增加语义检索模型。来源使用保存下来的引文及定位信息，作为文本展示，不执行 HTML，也不开放任意本地文件下载。

相对于原命令行方案，本版增加的是浏览器适配层。比较了 FastAPI/Flask、React/Vue 和 Streamlit；它们对多人服务或复杂页面有价值，本轮直接复用现有 Python 可减少依赖与迁移成本。服务固定绑定 127.0.0.1，写请求检查 Origin、页面令牌和 Host，限制正文大小和读取时间。它的定位是本机工具，尚无远程身份和多人权限设计。完整取舍见 [ADR 0025](decisions/0025-local-web-workbench-shared-review.md)。

## 尚未解决的问题

Codex 原生 hooks 的真实自动触发仍待验证，本版通过的是显式包装器。浏览器确认与 CLI 共库不改变这一限制。工作台搜索为子串筛选，Codex 召回仍用 V4.0 任务词匹配，同义表达能力有限。

本地服务无多用户认证、远程访问、批量审核或候选语义纠错功能；已确认事实的修正仍走原事件流程。审核修改支持事实内容、类型及生效时间，项目、事实键和来源保持固定。来源页保留引文与摘要，不归档完整原文件。

日期按 UTC 定义，当前日期默认取本机启动页面时的 UTC 日。自动可访问性检查仍有人工复核项。完整开发任务中的 Codex Windows 工具沙箱写入限制沿用 V4.0 记录，本版独立会话只验证注入与使用记忆。
