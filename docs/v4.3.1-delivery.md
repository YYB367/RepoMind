1. 选择项目并输入开发需求，点击“检查环境与相关记忆”。程序路径、Git、Python、登录及读写沙箱需通过，预查不调用模型。
2. 找不到 Codex 时先检查路径。发现顺序为 REPOMIND_CODEX_EXECUTABLE 显式绝对路径、当前 PATH、Windows Desktop 安装目录中最新的程序。可在启动服务前设置 $env:REPOMIND_CODEX_EXECUTABLE = 'C:/实际位置/codex.exe'；显式配置不存在时必须修正，不会静默换程序。程序检查失败会显示“尚未检查登录”，不应误判为凭据失效。
3. 点击“启动开发任务”，或从“最近任务”选已有记录。“运行反馈”显示从 started_at 起的已运行时间、最近执行事件的本机时间，以及当前命令/操作摘要。运行中每秒刷新计时，结束后固定；静默运行不会伪造进度。进程检查时间独立展示，不能证明命令已经完成。
4. 展开“失败记录与后续执行”，核对脱敏命令、原始退出码和失败输出摘录。首次失败始终保留；后续完全相同命令的结果单独展示。未提供退出码会明确标注。命令改写不自动认定为重试，未找到关联时显示未知；已有并行调用也不算重试。
5. 展开“命令记录”查看同任务后续执行。内部命令成功不等于任务成功，Codex 主进程退出失败有独立记录；状态“会话已结束”也不等于需求验收通过。结合助手结果、文件差异及测试证据判断。
6. 失败或中断后先核对文件与残留 Codex 进程，再决定是否创建新任务。工作台不自动重试，不会回滚已改文件；重启时将旧的排队/运行任务标为中断。旧任务没有的命令、原因和重试关系显示“旧版未记录”，不补造。
7. 候选审核、原文预览、确认和后续召回沿用原流程。新候选仍需用户确认；本版验收没有替用户批准新记忆。完整日常说明见 [网页指南](web-daily-guide.md)。

## 技术原理、变更原因与回滚

原版等待整个子进程结束后才解析输出，因此只有最终退出码。现在并行读取 stdout/stderr，逐行处理官方 Codex JSONL，再通过原 HTTP 轮询展示。队列限制内存，两个输出管道都排空以避免大量 stderr 阻塞；输入独立写入。SQLite 活动表与任务回执分离，既能中途读到事件，又不改写老任务原始 JSON。界面每秒只更新计时，轮询保留同任务已展开的命令和差异。

首次失败事件与后续执行是两份记录，通过命令摘要和出现顺序推定关联；调整命令不自动关联，也不把成功覆盖到首次错误。脱敏在保存之前完成，复用原凭据模式并补充环境值、命令参数和授权头规则。不保存模型推理文本。官方协议来源、方案比较、字段边界和取舍见 [ADR 0028](decisions/0028-runtime-feedback-and-codex-discovery.md) 与 [官方非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode)。

选择继续使用标准库、原 SQLite 和 1.5 秒轮询，是因为当前单机串行任务无需新增 WebSocket 服务、消息队列或前端构建。Desktop 程序目录只是本地 fallback，不当作官方稳定安装协议。没有扫描私有聊天来回填老任务。

只新增 web_task_activity，SQLite user_version 仍为 2，原账本和审核事务不变。停止服务后切回 v4.3.0 即可回滚代码；新表保留，旧版忽略它，不删除失败证据或覆盖正式记忆。旧版路径问题可能再出现。异常停止后仍需检查遗留子进程和文件。

## 限制与遗留问题

旧任务只有已保存的退出码，缺失正文不能恢复。一次本地 HTTP 测试发生连接中止，单项复测通过，根因尚未确定，仍保留该环境波动记录。Windows 的 Git 长路径限制已复现，跑全量测试应使用工作区内短临时目录，不要照搬较长的基准路径。重试关系仅支持同任务内完全相同的命令和记录顺序，参数调整或跨任务重试无法可靠自动关联。脱敏不是通用私人信息识别器，不要将凭据放入需求或命令。

单行 1 MiB、总输出 16 MiB，超限停止；命令事件最多 2000 条，超限明确显示不完整；命令/输出摘录各最多 8000 字，原因选已保存输出末 2000 字，保留截断标记。它不是完整终端存档或可直接执行的脚本。

仍为本机单用户串行工作台，无实时交互终端、自动重试或代码回滚。服务异常退出时，子进程及其工具可能需要人工核对；Windows Desktop 安装布局变化仍需实际预查。旧版文件预览的 ASCII 路径和 256 KiB 上限不变；原生 hooks 真实自动触发仍未新增补验。完成 V4.3.1 后停止。
