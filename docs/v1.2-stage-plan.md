# 阶段目标：完成 V1.2 Evaluation Platform，建立公平的记忆后端对照与可核验的 Langfuse 实验记录

设计基线：2026-10-27；分支 `feature/v1.2-evaluation-platform`。在已验收的V1.1之上，新增MemoryProvider对照、质量/延迟/实际usage报告，以及Langfuse trace、dataset、experiment同步。不开发V2代码执行Agent、OpenViking层级上下文或Harness优化。

## 本阶段输入、输出与边界

输入是既有事实账本、冻结的结构化查询与独立金标、显式Embedding配置，以及用户可选提供的Langfuse配置和价卡。输出包括四种variant的本地JSON/Markdown报告、可追踪来源的逐题结果、同步outbox及云端核验回执。

| variant | 做什么 | 允许得出的结论 |
|---|---|---|
| no_memory | 不取历史事实，返回无证据结果 | 衡量本数据对记忆的依赖；不是一个无记忆LLM编程Agent |
| repomind_semantic | 自研存储的纯向量候选检索 | 与Mem0受控配置比较检索后端 |
| repomind_hybrid | 自研向量加相同规则下的词法/RRF | 单独说明hybrid策略效果，不能把差异全部归因于存储后端 |
| mem0 | Mem0 OSS以infer=False存同样事实键文档，向量搜索后共享V1 resolver | 比较受控检索后端，不是完整Mem0原生抽取/纠错/端到端系统 |

V1/V1.1事件、数据、报告与运行入口保留。基础依赖继续轻量，Langfuse/Mem0等SDK位于可选platform extra；平台实验在独立v12虚拟环境安装锁定版本。业务数据仍以SQLite账本为准，Mem0本地索引可重建，不部署云数据库或Docker。

## 第一步：锁定公共SDK边界与版本

本轮实际核验候选版本为Langfuse **5.0.4**、mem0ai **2.2.1**，以最终锁文件和实际环境报告为准。Langfuse服务端v4、Python SDK v4/v5和Public API版本不是同一个概念。

2026-10-27官方overview/兼容矩阵已将Python SDK v5列为GA；部分reference仍沿用“latest v4”的说明。新SDK选择必须同时检查已安装公开接口和实际实验实现，不能仅凭“v4+”字样断言不会使用旧端点。本轮采用SDK5的OTEL tracing及experiment runner，避免将在2026-11-16移除的legacy trace/dataset-run路径。

Mem0仅使用已核验公共Memory/配置与本地Qdrant边界；2.2.1没有可用公共自定义实例注入或register_provider，因此通过公开OpenAI embedder配置连接本进程回环Embedding桥，转到既有Qwen/recorded provider，不patch私有工厂。infer=False跳过LLM提取，意外LLM路由拒绝。首次import前设置MEM0_DIR并关闭遥测，Qdrant/history全部归run目录；controlled环境排除spaCy/fastembed可选模型，防止隐式下载，报告注明dense-only。

## 第二步：实现统一MemoryProvider比较契约

统一输入为规范事实键文档、项目与known_at快照、查询文本、as_of、top_k、min_cosine及Embedding配置。统一输出为排序的事实键候选、原始/规范化分数、可计量usage、耗时和失败信息；最终值与证据一律交给共享V1 resolver。

公平控制项：

1. 四variant使用同样冻结问题与金标；有记忆variant使用相同事实键文档和已知时间过滤。
2. repomind_semantic与mem0使用同一Embedding模型、维度、输入文本、top_k和余弦门槛；Mem0评分度量与阈值含义须用已锁SDK/后端核验。
3. 所有候选先按项目和known_at隔离，命中键再取完整历史，由同一resolver解释plan、complete、correct及as_of；输入共同将换行规范化为空格并记录hash。
4. hybrid额外词法/RRF策略显式标注，不能把semantic与hybrid混成一次“后端胜负”。
5. offline recorded使用完全相同向量bytes；live各variant使用独立Embedding client与隔离索引，记录实际请求、usage、输入/向量hash及冷/热条件。live同model/text/params不保证逐次向量bit相同，差异必须flag，不归因后端。不把回放0token包装为真实成本优化，本轮不开发shared_live第三模式。

same model不自动等于same实验：文档构造、候选截断、过滤顺序、缓存、阈值和resolver都必须一致并写入配置。不会用不同公开benchmark分数排名，也不宣称复现Mem0默认行为。

## 第三步：质量、延迟、usage与价卡成本

质量报告至少包含完整查询正确率、已知键Recall@K、未知拒答、来源正确性、跨项目串用和逐题失败阶段。Recall分母与未知问题数量单独报告，不允许只报已知键召回掩盖未知误答。

计时记录准备、初始化、索引、search_and_resolution、评分、报告写入及另行同步。实现保留既有Provider公共search边界，故查询与resolver合并测量，不声称单独测得resolver耗时；这避免仅为计时改动已验收的V1规则。报告样本数、总时间及适用的分位数。四variant运行顺序、并发和冷/热策略固定记录，不把云端同步等待混进单后端查询延迟。小样本只能描述本次测量，不能保证生产性能。

Token只用服务实际返回usage。公共来源准备、每variant新增索引/查询调用、Langfuse同步分别归属，不重复计费或把未测费用写成0。相同事实若每variant实际重新Embedding，就分别计入各自实付调用；共享准备若只执行一次，则另列shared preparation。

默认cost=null，标注费用未测。只有用户提供明确模型、币种、计价单位、有效范围及输入/输出/缓存价格的价卡，才通过显式pricing配置估算，并注明是估算。缺少缓存token拆分时不能假定全部享低价；配置不足时继续报告未知，不猜“免费”。

## 第四步：冻结V1.2独立小数据集

新benchmark已独立冻结：3个新虚拟项目、30条结构化事件、12道dev与8道holdout；行数、分类与SHA-256见[data/v1.2/manifest.json](../data/v1.2/manifest.json)。金标人工编写，产品helper仅用于规范输入和计算待嵌入文档hash，不作为答案oracle。完整(subject,predicate)理想one-hot回放明确标test double；旧V1/V1.1冻结数据不改写。

先dev调试并固定配置，再首次holdout，保留首次失败及修复后结果。Mem0和自研读同样输入；本阶段比较重点是检索后端，避免把模型抽取质量混入后端比较。录制响应/向量是test double，必须与真实模型运行分开，不能证明真实语义质量。

## 第五步：Langfuse tracing、dataset与experiment

使用SDK5的OpenTelemetry observation上下文记录run、provider、query及可选generation，关联run_id、case_id、variant、输入hash、配置、实际输出/证据、分数和usage。dataset保存冻结输入/expected与版本信息；experiment在同一dataset和配置下比较variants。

本地评测完成后将预计算结果写入outbox；同步任务只读取既有输出与分数，不能为上传再次运行模型、再次搜索或修改金标。使用稳定run/trace/experiment标识追踪重试。SDK runner task返回既有output，evaluator返回既有score；不将同步行为计作模型推理成本。

不直接实现legacy `/api/public/ingestion` trace或`/api/public/dataset-run-items`上传；SDK5实验通过OTEL属性关联实验与items。SDK的dataset写接口与新Observations/Experiments读接口按锁版本验证。

## 第六步：outbox与云端验证状态

本地结果是独立可交付物，云端不可用时保留outbox和诊断，不能用云端故障抹掉本地评测。

| 状态 | 证据 | 可以声称什么 |
|---|---|---|
| local_only / pending | 本地outbox已落盘 | 可重放，尚未证明云端收到 |
| sent_unverified | 已调用SDK/flush，但缺少服务侧核对 | 已尝试发送，不能称云端持久化 |
| verified | 服务响应及新读API中查到对应dataset/experiment/observations/scores并核对payload | 本次对象已在服务侧核验 |
| retryable_failure | 网络、权限、读取滞后或字段不匹配 | 保存失败与可重试记录，不能改成成功 |

flush只表示SDK尝试排空缓冲，不证明云端持久化。sync至少一次语义；稳定trace ID不保证span exactly-once。重试先读服务侧已有对象并核对payload，ACK只跳过已经完整核验的内容。部分成功分对象保存回执，不能用一个dataset成功证明全部trace/experiment已同步。

Langfuse尚无用户配置时，不预设host、不猜地区、不自动开通服务。平台配置、模型key互相隔离；不把.env、key或未经允许的本地文件写入trace。SDK离线契约测试、真实SDK本地执行与cloudverified报告分别标记。

## 阶段验收与兼容回滚

本阶段至少满足：V1/V1.1回归保持通过；四variant比较协议可运行；Mem0真实锁版本SDK的本地持久化/范围/阈值测试通过；质量、来源、项目隔离、实际usage和成本缺失状态如实报告；Langfuse trace/dataset/experiment具备可重放outbox及服务侧核验路径。

没有Langfuse配置或服务侧ACK/读证据时，只能交付本地比较与SDK契约验证，明确cloud验证待完成，不能宣称整阶段平台联通已验收。未做真实模型的回放比较同样不能宣称真实质量改善。最终门槛、题数与实际结果在数据冻结后写入配置和验收报告。

V1.2新增功能通过optional import隔离，不要求原用户升级全部SDK。失败回滚可停用platform extra与新命令，恢复V1.1运行环境，保留本地报告/outbox及Mem0 run目录供检查；SQLite权威账本不改写。外部已创建对象不会随代码回滚自动撤销，重试与清理不得静默删除云端数据。
