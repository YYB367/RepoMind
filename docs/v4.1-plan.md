# 阶段目标

用本地浏览器审核 V3.1 / V4.0 的候选，并按项目、任务词和事实日期查询正式记忆。以 RepoMind 自身的真实记录验证网页审核、CLI 状态和新 Codex 会话召回的闭环。本版不进行策略调优。

## 实施与验收边界

复用 Python、SQLiteMemoryStore、ReviewQueue 和 MemoryResolver；仅增加本机 HTTP 入口与静态 HTML/CSS/JavaScript。每次请求单独连接 SQLite，审核调用原事务方法，以 revision 防止覆盖他人的修改。来源页只显示已保存的引文、路径、摘要和时间，不提供任意文件读取。

两个页面分别为待确认和项目记忆。候选支持筛选、查看证据、修改、确认、拒绝，以及查看历史审核状态。记忆页按项目搜索，在 UTC 事实日期与可选获知日期上复用原时间解析器，明确区分事实、计划和冲突。列表分页。

先运行隔离库的 HTTP / CLI 集成测试，再用真实试点库核对候选并通过浏览器审核。独立 codex exec 会话只收到任务，不由用户复制事实或来源。记录会话 ID、CLI 读回和浏览器截图。真实模型策略实验数为零。

## 界面设计

色彩：底色 #F3F6FA、纸面 #FFFFFF、正文 #202F43、操作蓝 #3659C9、确认绿 #19765E、分隔线 #D4DDE9。字体采用系统 Segoe UI / Microsoft YaHei UI，无远程字体请求；所有正文左对齐。

桌面布局：

~~~text
RepoMind        待确认 | 项目记忆            本地工作台
阶段标题与说明
项目选择 / 搜索 / 状态或日期                     查询
记录列表（约 1/3） | 事实与审核（约 2/3）
                 | 引文 / 路径 / 时间 / 摘要
                 | 保存修改 / 确认写入 / 拒绝
~~~

移动端改为纵向列表和详情。事实与证据的邻接关系是视觉重点，不使用统计卡片或装饰性图表。评审后将通用仪表盘式侧栏去除，改用仅两个页面的顶部导航；保留宽阔证据栏以支撑逐条核对。交互包含键盘焦点、加载/空白/错误状态和未保存修改提示。
